Workflow and Diagnostics API

Unreleased documentation preview — 13 October 2026

This manual includes unreleased interfaces and examples. It is not the documentation of an installed release. Model support and scientific acceptance remain as stated on each page.

BayesianMGMFRM.diagnostics — Function
diagnostics(fit::MFRMFit; view = :full, split_chains = true,
            rhat_threshold = 1.01, ess_threshold = 400)

Return a single diagnostic surface for the current minimal Bayesian fitting path. The result includes chain-level sampler rows from sampler_diagnostics, parameter-level rows from mcmc_diagnostics, block-level rows from parameter_block_diagnostics, and a compact machine-readable summary with rank-normalized R-hat, bulk ESS, tail ESS, compatibility metrics, and pass/fail counts. For the AdvancedHMC-backed NUTS path, the summary also reports divergent-transition counts, max-tree-depth hits, and the minimum available E-BFMI estimate across chains. The fields n_e_bfmi_expected, n_e_bfmi_available, n_e_bfmi_unavailable, and e_bfmi_complete distinguish that compatibility minimum from an all-chain E-BFMI gate. A chain is unavailable when any retained energy value is missing or non-finite.

Generalized diagnostic surfaces also include direct constrained rows. Coordinates fixed by a declared zero-dimensional raw transform remain visible with diagnostic_status = :structurally_fixed and quality_gate_applicable = false; they do not enter convergence extrema or failure counts. Constrained coordinates reconstructed from estimable raw coordinates remain quality-gate applicable.

The surrounding version-1 diagnostic payload is discriminated by its nested diagnostic_contract. Rows without :rank_normalized_rhat_bulk_tail_ess_v1 are pre-modern compatibility records and must not be relabeled as modern evidence. Under the modern contract, flag aliases rank_normalized_flag; use classical_compatibility_flag when the previous classical result is specifically required.

The compatibility default view = :full returns the complete diagnostic surface. view = :public keeps reader-facing diagnostic results while carrying explicit family and stability fields in a compact portable schema.

diagnostics(fit::MGMFRMFit; include_location = false, view = :full, ...)

Return the saved parameter and sampler assessment. With include_location = true, also compute location_rows and location_summary for fitted-person ability means, item difficulties, loading-weighted ability means and their differences. These equally weighted finite-panel quantities distinguish movement in a common location from movement in the response-relevant differences. Active loadings are used at every draw, including within-item Q structures. They are not population means, a new centering constraint, or a replacement for the original summary. Both views retain these optional diagnostics; default output is unchanged.

diagnostics(fit::MultidimensionalMFRMFit; view = :full, ...)

Return parameter, sampler and warmup diagnostics using the saved fit's settings. For between-item fixed-coefficient MFRM (including correlated and exchangeable rater models), location_rows adds rank-normalized R-hat and bulk/tail ESS for each dimension's finite-panel ability mean, item mean and their difference. location_summary summarizes these additional checks; summary retains the parameter/sampler assessment. The means equally weight fitted facet levels and are not population-mean parameters. Within-item or mixed Q returns location_status = :unsupported with an explanation. No sampling is performed.

BayesianMGMFRM.sampler_diagnostics — Function
sampler_diagnostics(fit; phase = :retained)

Return chain-level sampler diagnostics for a fitted minimal MFRM object. Rows include retained draw counts, warmup, step size, chain acceptance rate, finite log-posterior counts, and log-posterior summaries. This complements mcmc_diagnostics, which reports parameter-level R-hat and ESS. When the AdvancedHMC/NUTS backend is used, rows also include divergent-transition, tree-depth, step-size, and E-BFMI fields where available. For random-walk fits, n_nonfinite_proposals counts rejected non-finite proposals among retained iterations; these are not NUTS divergences. The count is missing for older fits without proposal telemetry and for other samplers.

Use phase = :warmup for separate chain-level warmup counts from new fits. AdvancedHMC, Turing and CmdStan report divergences, maximum-depth hits and nonfinite log densities. Generalized GMFRM/MGMFRM fits support AdvancedHMC and CmdStan. Random walk reports n_nonfinite_proposals during burn-in; it does not adapt its proposal scale. Its NUTS event fields are missing because they do not apply. All rows report expected/observed iterations. coverage is :recorded, :not_run (zero warmup), or :not_recorded (history unavailable); unavailable counts are missing. Warmup events do not enter posterior summaries, R-hat/ESS or retained-draw warning flags. No warmup pass/fail rule is applied. Older Turing fits without an explicit sampler_controls.nadapts record have unavailable history even when their requested warmup was zero: that request did not reliably disable adaptation. These summaries survive save_fit_cache/load_fit_cache; warmup parameter draws are not retained. The default phase = :retained preserves the existing diagnostic rows.

BayesianMGMFRM.mcmc_diagnostics — Function
mcmc_diagnostics(fit::MFRMFit; split_chains = true,
                 rhat_threshold = 1.01, ess_threshold = 400)

Return parameter-level convergence diagnostics for the current fitted draws. Rows include rank-normalized split R-hat, its bulk and folded components, bulk ESS, and tail ESS at the joint 10% tail probability. The compatibility fields rhat and ess retain the previous classical split R-hat and autocorrelation ESS values. The primary flag and rank_normalized_flag apply only the modern contract; classical_compatibility_flag records the previous diagnostic result without adding an undeclared quality gate.

These diagnostics require at least two independent chains. Rank-normalized ESS requires more than four draws per diagnostic chain after optional splitting; shorter runs return flag = :insufficient_draws. Non-finite or degenerate draws are never passed through as apparently usable diagnostics. Use sampler_diagnostics for backend-specific fields such as divergent transitions and tree depth.

BayesianMGMFRM.parameter_block_diagnostics — Function
parameter_block_diagnostics(fit::MFRMFit; split_chains = true,
                            rhat_threshold = 1.01,
                            ess_threshold = 400)

Summarize MCMC convergence diagnostics by identified parameter block. Rows aggregate the parameter-level R-hat and ESS diagnostics for blocks such as :person, :rater, :item, and :thresholds, while retaining block parameter names and machine-readable pass/fail counts. Empty blocks are returned with flag = :empty_block so reports can distinguish absent design terms from failed diagnostics.

BayesianMGMFRM.posterior_mcse — Function
posterior_mcse(fit; probabilities = (0.025, 0.5, 0.975),
               parameter_space = :auto)
posterior_mcse(draws; chains, parameter_names,
               probabilities = (0.025, 0.5, 0.975),
               parameter_space = :user_defined_estimand)

Estimate Monte Carlo standard errors for posterior means, standard deviations, and requested quantiles. Fit-based calls use identified parameters for scalar MFRM fits and direct constrained parameters for generalized and fixed-coefficient multidimensional MFRM fits by default; pass parameter_space = :raw_unconstrained to inspect generalized sampling coordinates or multidimensional MFRM free coordinates.

For fixed-coefficient multidimensional MFRM (independent or correlated, with either rater prior), the default reconstructs the last rater and item steps, retains fixed coefficients, and reports rho rather than Fisher z. Direct rows include block, dimension label, fixed/derived status and their actual parameter_space: :unit_logit, :dimensionless or :correlation. Free-coordinate rows use :unit_logit and, for correlated fits, :fisher_z. These labels describe units, not likelihood identification. Saved records and chain/iteration ordering are validated before computing MCSE.

The matrix method supports derived estimands: arrange rows in contiguous chain blocks, transform each draw to the quantities of interest, and supply one name per column. MCSE measures simulation precision only. Every non-fixed row keeps convergence_review_required = true, and no universal precision threshold or scientific decision is applied. Calls with fewer than two chains or fewer than 10 retained draws per chain return typed unavailable rows instead of presenting short-chain MCSE as usable evidence. Numerically undefined standard-deviation MCSE is reported as missing with :mcse_unavailable; separately available mean and quantile MCSE are retained. Autocorrelation estimation considers all available split-chain lags, using the initial-positive/monotone-sequence stopping rule rather than a fixed 250-lag cap. MCSE remains a precision estimate conditional on adequate sampling; it does not make a nonconverged chain valid.

For scalar/fixed-Q GMFRM/MGMFRM and normalized/correlated-2D MGMFRM results, estimand=:adjacent_logit_slope computes the same joint-draw quantities as posterior_summary(fit; estimand=:adjacent_logit_slope). Use the default parameter_space=:auto or :adjacent_logit_slope. This retains stored chain order and estimates mean, SD and requested endpoint MCSE separately; constant estimated traces are not declared structurally fixed. Correlated3D is separate.

BayesianMGMFRM.posterior_summary — Function
posterior_summary(fit; lower = 0.025, upper = 0.975,
    intervals = (0.66, 0.9, 0.95), reference = 0.0,
    rope = nothing, rope_probability_threshold = 0.95)

Summarize posterior draws for each parameter. Rows retain the legacy lower/upper interval columns and also include central credible intervals, probability of direction relative to reference, and optional ROPE/practical equivalence probabilities. Pass rope = r for a symmetric [-r, r] ROPE or rope = (lower, upper) for an explicit interval. probability_equal is the fraction of retained draws exactly equal to reference; a zero count is not evidence against a point-null hypothesis.

For GMFRMFit, MGMFRMFit, Experimental.NormalizedMGMFRMFit and Experimental.CorrelatedMGMFRMFit, use scale=:model for positive, constraint-restored model parameters, or scale=:raw for computation coordinates. Omitting scale preserves the historical raw-coordinate summary. The qualified direct_posterior_summary remains available with its original meaning.

For these same result types, estimand=:adjacent_logit_slope summarizes D*c_r*a_id from each joint draw (D=1 for scalar GMFRM; D=1.7 for MGMFRM). It returns fitted item × rater × dimension rows, including structural Q zeros and fixed slopes. These are conditional adjacent-category log-odds changes per one ability unit, not cumulative-event odds, reliability or standardized effects. Other ability components are held fixed. Matching units does not align constructs or priors across models. This estimand rejects scale=:raw; scale=:model is optional. Use the same estimand in posterior_mcse for simulation precision. No samples are refitted, rescaled or reordered. Inspect whole-fit diagnostics. The separate Correlated3D record/report API is outside this selector's scope.

BayesianMGMFRM.posterior_contrast — Function
BayesianMGMFRM.posterior_contrast(fit; left, right,
    operation=:difference, interval=0.90, rope=nothing)
BayesianMGMFRM.posterior_contrast(left::AbstractVector, right::AbstractVector;
    chains, log_ratio=false, interval=0.90, rope=nothing)

Compare two named model coordinates within a saved scalar MFRMFit, independent MGMFRMFit or Experimental.NormalizedMGMFRMFit. Use exact names from BayesianMGMFRM.recovery_quantities(fit).rows, including the dimension label for multidimensional abilities. :difference accepts two persons in the same dimension or two rater severities. :log_ratio accepts two positive rater consistencies. Other coordinate combinations, repeated names and two structurally fixed quantities are rejected. Scalar MFRM differences use unit logits, including reference or hard-anchored raters reconstructed at their fixed values; external anchor uncertainty is excluded. Its RSM and PCM threshold choices are supported. GMFRM, fixed-Q multidimensional MFRM and correlated MGMFRM are outside this method.

Compute left minus right, or log(left) minus log(right), at each original joint posterior draw. Preserve complete chain order and reconstruct constrained model coordinates, including the final rater. No fitting, resampling, scale linking or subtraction of marginal interval endpoints occurs. Differences use the fitted ability/severity units; do not compare different dimensions or different fits.

summary retains the mean/SD, central equal-tailed interval, endpoint/mean/SD MCSE, contrast-specific rank-normalized split R-hat and bulk/tail ESS. It also reports P(contrast > 0). Optional rope=(lo,hi) uses inclusive bounds, on the difference or log-ratio scale, and reports probabilities below/inside/above. Constant sampled events have unavailable MCSE, not proof of zero uncertainty. Log-ratio ratio_interval exponentiates the median and interval endpoints; it is not a mean ratio, and MCSE remains on the log scale.

Whole-fit warnings remain in whole_fit_diagnostics and sampling_warning; good contrast diagnostics do not override them. No numerical threshold, practical-equivalence rule, fairness label or automatic decision is applied. The result includes coordinate units, model/prior/source identities, original chain/iteration IDs and an evaluated-draw hash. Save the result with its native fit and original environment; it is not a portable posterior-draw format. The vector method preserves the existing paired-summary calculation for already extracted draws. It returns summary directly, requires equal contiguous chain blocks, and cannot verify source identity, units or whole-fit diagnostics. The caller must retain joint pairing and supply the complete original chains; use the fit method when a supported saved fit is available. This operation does not promote the underlying experimental model to Supported.

BayesianMGMFRM.loo — Function
loo(fit::MFRMFit; ndraws = nothing, draw_indices = nothing,
    rng = Random.default_rng(), pareto_k_threshold = 0.7,
    tail_fraction = 0.2, min_tail_draws = 5)
loo(design::FacetDesign, draws; kwargs...)
loo(loglik::AbstractMatrix; kwargs...)

Compute a raw importance-sampling leave-one-out (LOO) estimate from posterior pointwise log-likelihood draws. The log-likelihood matrix must have dimensions draws-by-observations. The returned named tuple includes elpd_loo, p_loo, lppd, looic, standard errors, raw-importance effective sample sizes, and a Hill-estimated Pareto-k diagnostic for each observation.

This helper does not perform PSIS smoothing. Treat rows with pareto_k above pareto_k_threshold as unstable and prefer exact LOO, K-fold cross-validation, or model-specific follow-up before making strong model-comparison claims.

BayesianMGMFRM.psis_loo — Function
psis_loo(loglik; chain_ids=nothing, r_eff=nothing, pareto_k_threshold=0.7)
psis_loo(fit; kwargs...)
psis_loo(design, draws; chain_ids=nothing, r_eff=nothing, kwargs...)

Standard PSIS-LOO using the reference-checked Zhang–Stephens tail fit. Matrix rows are draws and columns are observations. Supply contiguous, equally sized chain_ids to estimate relative efficiency from likelihood values, or positive r_eff (scalar or one per observation). Without either, matrix inputs assume independence and return an explicit warning. Fitted inputs use all retained chains in their original order; subsampling is refused.

tail_fraction=.2 and min_tail_draws=5 are retained compatibility keywords; other values are rejected because standard PSIS selects its tail from S and relative efficiency. The diagnostic threshold defaults to .7 and may be set explicitly. Constant or insufficiently variable tails retain infinite Pareto-k and a warning, not evidence of perfect precision. Reported pointwise SE is not MCMC MCSE or a crossed-cluster SE; no refitting or automatic selection occurs.

The former Hill approximation remains available through criteria(fit; criteria=(:hill_smoothed_loo,)). Historical results are unchanged.

loo_refit(data::FacetData, plan = loo_refit_plan(data);

Execute exact leave-one-observation-out refits for a loo_refit_plan under the current fit-supported MFRM/RSM/PCM likelihood, or under the guarded experimental GMFRM/MGMFRM likelihood when experimental = true is supplied. Each plan row is refit on the complementary training observations, scored on its single heldout observation, and summarized with the same heldout log-score contract as kfold.

Before fitting, all plan rows must have disjoint heldout/training sets with training equal to the full heldout complement. Check whether each training fold in a kfold_plan retains the levels needed to score its heldout observations. Rows are reported by fold and facet for person, rater, item, score category, and optional facets by default. Execute heldout K-fold refits for a kfold_plan under the current fit-supported MFRM/RSM/PCM likelihood, or under the guarded experimental GMFRM/MGMFRM likelihood when experimental = true is supplied. Each fold is refit on its training observations, scored on all heldout observations in that fold, and summarized with the same heldout log-score contract as kfold.

All folds are validated before the first fit. Each training set must be the full heldout complement; K-fold holds out every observation exactly once, with at least two nonempty folds. predictive_check(fit::Experimental.ThreeIndicator.ConcurrentWorkflow.Fit;
    seed, interval=.95, conditioning=:existing_levels, qualification_report=nothing)

Perform a posterior predictive check, using parameters from the fitted posterior and generating new categorical responses. This is not a prior predictive check: it does not draw parameters from the prior. The report records check_type="posterior_predictive" and parameter_source="fitted_posterior". posterior_predictive_check(fit; ...) is an equivalent existing entry point.

Every complete retained joint state generates one 9/9/2 response table on the observed design, conditional on existing effects and histories. Study panels, score direction, chain/iteration IDs and baseline numerical warnings remain. Outputs are marginal and A/C joint counts plus maximum joint-cell discrepancies. No new-level, held-out or prior predictive generator is supplied for this target.

The Saved-fit Reporting API groups the common reliability, agreement and category reports.

Compare observed and expected ratings

Use calibration_table to ask whether groups of observed rating rows have averages close to their model expectations. Its fitted-result methods accept MFRMFit, GMFRMFit and MGMFRMFit; the experimental normalized and correlated result types have separate reporting contracts. A model family name alone does not establish that this function accepts its result type.

For an existing supported fit, use all its retained draws without refitting or generating replicated outcomes:

rows = calibration_table(fit; target=:expected_score, bins=10, interval=0.9)
points = calibration_plot_data(rows)
[(; bin=p.bin, ratings=p.n_observations, observed=p.observed_mean,
    expected=p.predicted_mean, lower=p.predicted_lower,
    upper=p.predicted_upper, probability=p.interval_probability) for p in points]

Group rows by target and category before drawing multiple series. Put predicted_mean on the horizontal axis and observed_mean on the vertical axis, with the equality line as a reference. Display n_observations in the table or point labels; it counts rating rows, not unique people. n_draws is the number of selected parameter draws and is not an effective sample size.

Each bin is formed from posterior mean predictions, separately for each target. The observed and expected means use the same rows with equal rating weight, retaining their item and rater conditions. These are not ability-conditioned response curves, a standardized reference panel, or independent held-out predictions. Tied predictions can be split across bins to balance row counts; the reported prediction ranges may therefore touch or overlap.

The horizontal interval is an equal-tail posterior interval for the bin's mean expected value. Its probabilities travel with the plot data. It is different from the range of row predictions (predicted_bin_lower/upper), a prediction interval for replicated ratings, and Monte Carlo uncertainty. :outside_interval describes a discrepancy; it is not a calibrated significance test or a reason to remove a person, rater or category. Sampling diagnostics and the precision needed for the analysis must be assessed separately.

For a category-use proportion, request target=:category_probability and an explicit score label with category=.... An ordinal high-score category is not automatically a correct answer. For variation in replicated ratings use posterior_predictive_check; that operation generates new outcomes. For conditional category curves across more fitted-result types, use the owner-aware category_report described below.

The plot-data conversion accepts older reduced rows, preserving available values and returning missing for absent counts, median or interval probabilities. Keep the complete calibration table and its fit/report provenance; the plot rows alone do not archive the model, source environment or diagnostics.

For owner-aware category summaries across the eight common saved-fit types, use BayesianMGMFRM.category_report. Its expected-use posterior intervals differ from the replicated-use intervals below. Optional profiles specify the item, rater, plotted dimension and every fixed other ability. Request it through fit_report(...; reporting=(; category=(...), ...)) to add the distinct category_report section; the historical section below keeps its original interpretation.

For a fitted minimal MFRM/RSM/PCM model, category-use and pairwise rater diagnostics can be requested without changing the fitted data or model:

categories = category_functioning_summary(
    fit_result;
    ndraws = 200,
    min_count = 5,
)

raters = rater_homogeneity_summary(
    fit_result;
    ndraws = 200,
    severity_rope = 0.10, # use a substantively declared margin
)

categories.usage_rows and categories.threshold_rows retain predictive and step-order review flags, but never collapse categories automatically. raters.contrast_rows computes paired severity differences; a positive severity_a - severity_b means rater A is more severe. Coordinate rows identify the default fixed reference, declared hard anchors, and estimated severities. A two-fixed-coordinate contrast is an exact constant with zero uncertainty draws, a not-applicable interval type and interval probabilities, and deterministic sign/ROPE probabilities. A one-fixed-coordinate contrast has posterior uncertainty only from the estimated side. A ROPE is not assumed unless the analysis supplies one.

fit_report includes both summaries by default for stable MFRM fits: category_functioning.usage_rows, category_functioning.threshold_rows, and rater_homogeneity.contrast_rows are available in structured, public, Markdown, JSON, and table outputs. Category review flags become one aggregate report warning and never cause automatic recoding. Set include_category_functioning = false or include_rater_homogeneity = false for an independent opt-out. Generalized fits leave both stable-only report sections unrequested by default and return unsupported if either is requested explicitly. A one-rater stable fit returns zero contrast rows with contrast_availability = :not_applicable_single_rater; the empty pair set is not labelled connected evidence of homogeneity. Empty row fields survive public JSON, table, and bundle round trips. Markdown omits empty previews unless include_empty = true is requested.

For PCM reports using an explicitly declared category scale, unobserved endpoints remain present as skipped category-use rows and do not reduce the item-specific threshold-row universe.
