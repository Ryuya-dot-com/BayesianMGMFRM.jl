保存済みモデルの予測比較・回復評価：隔離したAPI候補

Unreleased documentation preview — 12 October 2026

This manual includes unreleased interfaces and examples. It is not the documentation of an installed release. Model support and scientific acceptance remain as stated on each page.

この候補は、MFRM・GMFRM・MGMFRM、正規化／相関付きMGMFRM、固定Qの多次元MFRMの 保存結果を、同じ評定への予測で比較し、名前付き真値に対する回復評価へつなぎます。 現在の本体に統合・公開したAPIではありません。 候補ディレクトリを julia --project=. で読み込んで使用します。 以下の保存結果を評価する関数は新しい事後推定を行いません。K-foldには別途、各foldの学習fitが必要です。 引数と戻り値は候補APIリファレンスから確認できます。

知りたいこと使用する経路現時点で分かる範囲
同じ評定に対するモデルの予測差compare_predictions学習データのWAIC／raw IS-LOOによる記述的比較
学習から除いた評定に対する予測差prediction_refit_plan → prediction_fold_observations → prediction_kfold → compare_kfold_predictions保存済み学習fitのK-fold比較。予測は既存水準に条件づける
生成時の真値をどの程度回復したかrecovery_quantities → recovery_evaluation一つのデータセットでの名前付きの量の評価とMCMC MCSE
同じ設計・真値を繰り返した場合の性能recovery_replications全予定反復を残した量別集計。反復間SEには独立性の根拠が必要

いずれも自動的なモデル採用、構成概念の妥当性、必要人数・評定者数の保証を返すものではありません。

モデル名だけで選択を決めず、何を知りたいかを先に区別します。 固定係数と推定係数の違い、次元数とQ行列の違い、能力間相関の有無は別の選択です。 比較表には各モデルの次元・Q・尺度・相関・事前分布などの情報を残します。 異なる次元の能力成分を直接対応させる機能ではありません。

保存から比較まで

既存の save_fit_cache(path, fit) で保存した結果を使います。次の例のIDは、実際のデータで 永続的に管理している評定IDに置き換えてください。一人が付けた評定や同一反応に対する 複数評定も、一つひとつを区別します。単なる行番号の一致ではデータの対応を保証できません。

using BayesianMGMFRM
include("examples/saved_model_comparison.jl") # 候補プロジェクトのルートで実行

result = saved_model_comparison(
    "MFRM" => "mfrm.jls",
    "GMFRM" => "gmfrm.jls",
    "MGMFRM D2" => "mgmfrm-d2.jls";
    dataset_id="rating-study-v1",
    observation_ids=rating_ids,
    comparison_axis=:dimensions,
    criterion=:waic,
    baseline="MFRM",
    se_unit=:none,
)

[(; row.model, row.elpd_difference, row.se_elpd_difference,
    row.sampling_warning, row.criterion_warning,
    row.problem_observation_ids) for row in result.rows]

メモリ上のfitにも BayesianMGMFRM.compare_predictions("MFRM"=>fit1, "GMFRM"=>fit2; ...) を使えます。取り出し済みの BayesianMGMFRM.prediction_observations(...) の結果を比較する場合は、 その結果が既にデータIDと評定IDを保持するため、比較時のID指定を省きます。 全fitまたは全予測結果のどちらかを渡し、両者を混在させません。

行順が違う場合は observation_ids=Dict("MFRM"=>ids1, "GMFRM"=>ids2, ...) として、 各fitの元の行順でIDを指定します。得点、人物・課題・評価者のラベル、追加ファセット、 カテゴリ定義、学習データ全体の結合を照合してから、基準モデルの行順に揃えます。 どの入力も変更しません。異なる推定の標本をdrawごとに対にする必要はありません。 各モデルの全チェーン・全保持標本を使い、部分抽出・並べ替え・再標本化したdrawは拒否します。

比較軸・評価指標・不確実性

引数意味
comparison_axis=:model次元数とQを一致させる。モデル族などの差はメタデータを確認する
:dimensions次元数とQの違いを許可する。同じ観測への予測を比較する
:q_matrix同じ次元数でQの違いを許可する
criterion=:waic元の観測別log likelihoodから既存のWAICを計算する
:raw_loo平滑化しない重要度サンプリングによるLOO。重みの不安定性を確認する
:hill_smoothed_loo既存のHill方式。標準実装との同等性を検証したPSISではない
se_unit=:none既定値。差の標準誤差は missing とし、推測上の単位を暗黙に決めない
:observation評定単位を交換可能とみなす近似標準誤差
:person人物内のELPD差を合計し、人物単位を交換可能とみなす近似標準誤差

評定ごとのELPD差を d_i とすると、:observation のSEは sqrt(N * var(d)) です。 :person は人物ごとの和 D_g を作り、sqrt(G * var(D)) とします。 一単位しかなければSEは未定義として missing を返します。これは一方向の集計による近似で、 課題・評価者が交差する依存を一般的に補正するものではありません。明示的な指定は 交換可能性の成立を証明しません。いずれもMCMCのMCSEや独立反復に基づく設計シミュレーションのSEではありません。

elpd_difference は「そのモデル − 基準モデル」で、正ならその評価指標上で高い値です。 行順は入力順を保ち、勝者、自動採用、事後モデル確率を返しません。標準誤差や警告が 未解決のまま、点推定の順位だけで採用を決めないでください。

ここでの評価対象は、仕様と水準集合を固定した、一つの評定を除く予測の近似です。 入力は学習時の既存水準への条件付き予測です。人物全体・評価者全体・課題全体を除く 交差検証、新水準への積分、再推定によるK-foldではありません。 予測単位と除外単位を問いに合わせる必要があります （loo FAQ）。

診断と互換性

各行はサンプリング警告、評価指標の警告、問題のある評定ID、保持標本数、モデル情報と 保存標本のhash（対応形式の場合）を保持します。警告のあるモデルを除外して比較母数を変えません。 status=:descriptive も科学的受入れを意味しません。MCMCの比較MCSE、相対効率補正、 交差クラスタ補正は未計算です。予測の良さは構成概念の妥当性や区間被覆の保証でもありません。

候補のschemaは bayesianmgmfrm.prediction_comparison.v1 です。取り出し／指標のschemaは それぞれ bayesianmgmfrm.prediction_observations.v1 / bayesianmgmfrm.prediction_criteria.v1 です。 以前の .prototype.v1 bundleは、保存fitから候補APIで再度取り出してください。 既存の compare_models と sensitivity_comparison、保存fit形式、ルートのexport一覧は変更しません。 候補APIは BayesianMGMFRM. を付けて呼び出します。候補の結果形式の最終確定は独立レビュー後です。

この候補の検証は、解析的スコア、合成標本、保存・再読込、入力拒否、既存関数との互換性が対象です。 モデル選択の正答率、実データへの科学的推奨、設計計画の精度保証、パッケージ全体の公開完了は含みません。

MGMFRMと固定係数の多次元MFRMのレポート

この候補では、次の保存結果型の fit_report / save_fit_report_bundle に 同じ引数でWAICとraw IS-LOOを接続しています。診断・予測要約・保存機能は既存の経路を使います。

対応型モデル
Experimental.NormalizedMGMFRMFit正規化事前、能力の母集団相関は単位行列
Experimental.CorrelatedMGMFRMFit2次元の相関付きMGMFRM
MultidimensionalMFRMFit固定Q係数・unit-logit尺度の独立多次元MFRM（現行のcanonical記録）
Experimental.CorrelatedMFRMFit同じ固定係数モデルの2次元相関版
Experimental.ExchangeableMFRMFit交換可能な評定者事前、独立／2次元相関の両方

係数を固定するか推定するか、次元数とQ、相関構造、評定者事前の違いを 同一モデルとして扱いません。レポートのモデル・事前・尺度の記録はそれぞれ保持します。 旧fixed-Q v1記録は共通比較・指標計算で読み取れますが、公開レポートは従来どおり拒否します。 保存されたモデル指定の意味が異なるためで、形式名だけを書き換えて移行しないでください。

fit = load_fit_cache("mgmfrm.jls")
report = fit_report(fit;
    dataset_id="rating-study-v1", observation_ids=rating_ids,
    include_waic=true, include_loo=true,
    draw_indices=[1, 2, 2], # 事後予測の表示だけに使用
    require_complete=true,
)
save_fit_report_bundle("mgmfrm-report", report; require_complete=true)
restored = load_fit_report_bundle("mgmfrm-report"; require_complete=true)

include_waic と include_loo の既定値はともに false です。指定しなかった項目は :not_requested と表示します。旧レポートの :unsupported はそのまま読み込めます。 計算を要求した場合はデータIDと一意な評定IDが必須です。IDだけ渡して評価指標を要求しない 呼び出しも拒否します。既存3型のレポート引数・既定値は変更していません。

WAIC／LOOは、上の draw_indices と独立に全チェーン・全保持標本を使います。 .waic / .loo の rows に総ELPD、近似SE、標本数、警告、diagnostic_rows に観測別の ELPDと診断・評定IDを残します。problem_observation_ids は指標の警告対象です。 problem_rows は警告対象だけの表で、全観測表の後半にある問題もプレビューで確認できます。 Markdownは指定した行数までのプレビューで、JSONと表ファイルには全対象を保存します。 LOOの設定は loo_threshold=0.7、loo_tail_fraction=0.2、loo_min_tail_draws=5 です。 レポートのLOOは平滑化しない方式に限定しています。閾値の変更は診断の表示条件を変えるもので、 計算精度や科学的な受入れを保証しません。

パラメタ推定のMCMC誤差には posterior_mcse(fit) を使います。正規化／相関付きMGMFRMでは レポートの direct_posterior.mcse_rows にも入りますが、固定係数MFRMのレポートへ この表を追加する変更は行っていません。WAIC／LOOの se_elpd は観測間のばらつきに基づく近似SEで、MCMC誤差も交差クラスタ依存も補正していません。 警告とこの解釈を、公開表示、Markdown、JSON、表、保存・再読込まで保持します。 両指標は別々の節として計算し、一方のエラーで他方の計算済み結果を消しません。 on_section_error=:capture ならエラーを記録した不完全レポートになり、 require_complete=true ならその状態を拒否します。 :computed や report_status=:complete はレポート生成の状態であり、推定の合格判定ではありません。

examples/saved_mgmfrm_report.jl は上記5型の保存fitから公開表示の新しいレポートを作る 再推定なしの例です。固定係数MFRMでも同じ関数を呼べます。 examples/normalized_mgmfrm.jl はデータ作成からの短い操作例で、評定IDも保存します。 後者の短いMCMCは推論に不十分です。既存の推定・診断・MCSE・図の検証証拠を再利用し、 今回の追加検証では保存済みfitから新しいレポート経路だけを実行します。 K-foldの学習用要求と保存済みfoldの採点は、以下の共通APIで扱えます。 保存した全foldの集計比較は後述の経路で利用できます。複数モデルの自動再推定、新水準予測、 参照PSIS、科学的なモデル選択性能の検証は未完了です。

K-foldの学習データを固定し、保存結果で保留データを採点する

知りたいことが「既知の受験者・評定者・項目における、未観測の評定をどれだけ予測できるか」なら、 学習データだけで推定した各foldの事後標本で保留評定を採点します。 学習データ上のWAIC/LOOとは別の結果です。新しい受験者や評定者への一般化には、別の予測対象と 周辺化が必要です。同じ反応の複数評定をまとめて保留するかも、分析目的に合わせて事前に決めます。

using BayesianMGMFRM, Serialization

# data/spec、prior、永続的な rating_ids、分割方針は事前に決める。
plan = kfold_plan(spec.data; k=5, group_by=:response_id)
prepared = BayesianMGMFRM.prediction_refit_plan(spec, plan;
    prior=MFRMPrior(), dataset_id="rating-study-v1", observation_ids=rating_ids)
request = prepared.folds[1]
serialize("fold-1-request.jls", request)

# scalar MFRM の実行例。サンプラー設定は解析計画に従う。
training_fit = fit(request.model; prior=request.prior,
    chains=4, warmup=1000, ndraws=1000)
save_fit_cache("fold-1-fit.jls", training_fit)

# 再開時は同じ request と、対応する学習データの保存結果を使う。
include("examples/saved_fold_predictions.jl")
scored = saved_fold_predictions("fold-1-fit.jls", deserialize("fold-1-request.jls"))
scored.pointwise_loglikelihood   # draw × heldout rating
scored.observation_ids          # この列順に対応する永続ID
scored.sampling_quality         # 診断警告をそのまま保持

準備・採点API自身は推定を実行しません。全データの事後標本も不要です。 GMFRM、MGMFRM、正規化MGMFRM、固定Q多次元MFRM、および対応する相関・交換可能事前分布の 場合は、対応する Experimental のモデル・事前分布を準備時に明示し、 Experimental.fit(request.model; prior=request.prior, ...) で推定します。 モデルごとの既存の次元・Q・事前分布・バックエンド制約は維持されます。 例の反復数だけで推定精度が保証されるわけではありません。

準備時には全foldの分割の完全性と既知水準の条件を調べます。学習データは保留データの完全な補集合で、 各評定は一度だけ保留されます。通常の FacetData(table) は水準を一定の順に並べます。異なる水準順で明示的に符号化された入力でも、 学習データでは元の順序を維持し、「最後の水準」が入れ替わって再構成座標上の事前分布が 別のラベルに移ることを防ぎます。Qの項目対応、次元名、 事前分布の尺度、相関構造も維持します。メタデータのグループを指定しても新しい効果を推定するわけではありません。

採点時には要求の変更を検出し、実際の学習データ・モデル・事前分布・相関構造の同一性を確認します。 全データのfit、別の事前分布、別のLKJ設定、壊れた保存標本などは拒否します。相関付き標本に 相関変換をもう一度かけることはありません。固定MFRMの旧v1形式を自動で移行する機能もありません。

全保持標本・全チェーンを使い、診断不良の標本を黙って捨てません。include_probabilities=false で カテゴリ確率配列の確保を省けます。返る尤度には事前分布やJacobianを加えません。 元データと永続IDを結合した source_binding、分割を結合した split_binding は、同じ入力・分割なら モデルや次元が違っても一致します。学習ターゲットの識別子はモデル・事前分布も含むため別です。 これらは意図しない取り違えを防ぐもので、推定の収束や実行履歴を証明するものではありません。 保留結果を prediction_criteria に渡して学習用WAIC/LOOとして計算することは拒否します。

全モデル・全foldの自動推定は行いません。保存済みの学習fitを使う集約・比較は次の経路で行います。 同じ観測数や位置番号だけでは異なる結果を集約せず、元データ・分割・予測対象の対応を確認します。 また、保留結果を見た後に事前分布やモデルを調整したかどうかは、このAPIでは検出できません。 図の描画と推定本体は変更しておらず、今回の検証には含めません。

保存した全foldの集約とモデル比較

同じ元データ・永続ID・分割を使って、モデルごとに prepared を作ります。 各foldの学習fitを保存したら、次の例で保留評定の採点から比較まで進められます。 prepared 自体も Serialization.serialize で保存し、再開時には同じものを読み込みます。

include("examples/saved_kfold_comparison.jl")

result = saved_kfold_comparison(
    "MFRM" => (; prepared=mfrm_prepared,
        caches=Dict(1=>"mfrm-fold-1.jls", 2=>"mfrm-fold-2.jls")),
    "MGMFRM D2" => (; prepared=mgmfrm_prepared,
        caches=Dict(1=>"mgmfrm-fold-1.jls", 2=>"mgmfrm-fold-2.jls"));
    comparison_axis=:dimensions, baseline="MFRM",
)
[(; row.model, row.elpd, row.elpd_difference, row.complete,
    row.status, row.sampling_warning, row.se_elpd_difference) for row in result.rows]
result.rows[1].folds # foldごとの状態・診断・失敗理由・保存標本の識別子

この例は2-fold用です。実際には準備した全foldのIDとキャッシュの対応を渡します。 モデルの軸は先の比較と同じく :model、:dimensions、:q_matrix を明示します。 相関・係数・次元・事前分布は model_contract に保持し、モデル名だけから差の原因を推測しません。 結果の行順は入力順、差は「各モデル − 指定した基準モデル」です。自動的な順位、採用モデル、重みは返しません。

既に採点してあれば、BayesianMGMFRM.prediction_kfold(prepared, scores; failures=...) で集約し、 BayesianMGMFRM.compare_kfold_predictions("MFRM"=>a, "GMFRM"=>b; comparison_axis=:model) で比較できます。採点結果のfold順は任意です。評定の行順がモデル間で違っても永続IDで揃え、 得点・各ファセットのラベル・カテゴリ・分割を照合します。全保持標本と全チェーンを使います。

状態集計と比較での扱い
全foldあり、診断警告なし全評定のELPDと基準モデルとの差を返す。科学的受入れとは別
全foldあり、診断警告あり該当foldとモデルを残し、値を記述的に返す。比較全体も警告状態
結果未到着該当foldは :missing。全体ELPDは missing。到着済み評定の値は点検用に保持
明示した実行失敗failures=[fold_id=>"失敗理由"] を渡すと :failed。欠測と区別して保持
比較候補の一つでも未完了完了済みモデルの値は残すが、全モデルの比較差を missing にする
重複、異なる分割・ターゲット、変更された保存内容エラー。欠測へ黙って置き換えない

保存例の各モデルにも failures=[2=>"storage failure"] を加えられます。そのfoldは caches に含めません。 診断不良を実行失敗として捨てることも、成功したfoldだけの和を全体ELPDとして扱うこともしません。 diagnostics_ok は保存結果の診断フラグに基づき、収束や性能の保証ではありません。

評定 i のスコアは、対応する学習事後分布の標本 s に対する log(mean(exp(loglikelihood[s,i]))) です。対数尤度の平均ではありません。 グループごとに保留した場合も、ここで返す値は評定別の周辺予測スコアの和です。 グループ内の尤度を先に掛け合わせた同時予測密度とは区別します。

この経路では標準誤差、MCMCのMCSE、独立反復に基づく不確実性はすべて未計算と明示します。 foldを独立反復とみなしたSEも、既存の単純な評定別SEも自動では転用しません。 点差だけで方法を採用したり、実質的な優劣が確定したと扱ったりするための検証には未到達です。 新人物・新評価者・新課題への周辺予測や、保留結果を見たモデル調整への補正も含みません。

準備結果と採点結果は、この未公開候補で v2 に更新し、完全なfold一覧と結果内容のhashを保持します。 旧候補の準備結果・採点結果を集約する場合は、同じ仕様と分割から準備し直し、対応する既存fitを再採点します。 fitキャッシュ形式やfold要求の v1 は変更せず、新しいMCMCは不要です。hashは意図しない変更の検出用で、 実行履歴の認証やデータ漏洩の不存在の証明ではありません。

設計シミュレーションのための共通回復評価

BayesianMGMFRM.recovery_quantities(fit) と BayesianMGMFRM.recovery_evaluation(fit, truth; ...) は、同じ8種類のfitについて、モデル上の名前付きの量を真値と照合する入口です。 これは一つのデータセットの保存標本を評価する機能です。新しいデータ生成、推定、独立反復の集約、 SBCの実行、必要人数・評定者数の推奨は行いません。固定係数MFRMには現行の正規の記録形式を使い、旧v1を拒否します。

using BayesianMGMFRM, Serialization
include("examples/saved_recovery_evaluation.jl")

fit = load_fit_cache("simulation-fit.jls")
catalog = BayesianMGMFRM.recovery_quantities(fit)
[(; r.parameter, r.block, r.dimension_label, r.parameter_space, r.fixed)
    for r in catalog.rows]

# 生成時に保存した、モデル上の名前 => 真値の辞書。
# 事後平均などから真値を作らず、生成モデルと分析モデルの対応を先に定める。
truth = deserialize("truth-model-coordinates.jls")
evaluation = saved_recovery_evaluation("simulation-fit.jls", truth;
    dataset_id="design-A-replication-001", observation_ids=rating_ids, interval=.95)
evaluation.rows
evaluation.sampling_quality

辞書には評価したい量だけを指定できます。名前の誤り、空の辞書、非有限の真値、[-1,1]を外れる相関の真値、重複した評定IDは拒否します。 各量の結果は元のモデル上の順序を保ち、辞書の順序には依存しません。 カタログには推定値の列だけでなく、ネイティブの再構成が対応する最後の厳しさやステップ、相関、 構造上の固定値も含めます。derived=missing は既存の経路に由来情報がないことを表し、独立したパラメタという意味ではありません。

真値は、一覧に示された尺度・人物等のラベル・識別制約に対応している必要があります。 固定係数MFRMはunit-logit尺度、一般化モデルはそのモデルの尺度を保ちます。相関はrhoとして評価し、 Fisher zのまま照合したり、既に相関を持つ能力標本に再度相関変換をかけたりしません。 一次元と多次元の能力の対応、異なるモデル間の尺度変換、真値の中心化は自動では行いません。 同じ名前が現れることだけでは、モデル間で同じ推定対象を意味するとは確認できません。 例えばGMFRMでは項目難易度が和0で厳しさは自由ですが、MGMFRMでは厳しさが和0です。 GMFRMの項目識別力と評定者一貫性は無次元で、位置の尺度とは分けて表示します。

出力意味と限界
posterior_mean, posterior_sd, posterior_lower/upper全保持標本・全チェーンから得た、指定幅の中央信用区間等
bias今回の事後平均 − 真値。独立反復から推定した平均バイアスではない
squared_error, interval_width, covered一つの量・一つのデータセットでの評価値。covered は推定される量のみに適用
fixed, coverage_applicable固定された量では covered=missing、coverage_applicable=false。点区間を較正の証拠に数えない
fixed_value_matches_truth固定値と指定真値の一致。不一致を警告として残し、真値を自動で合わせない
mcse同じ量の平均・SD・区間端点等の、既存手法によるMCMC MCSE。利用できない場合は状態と missing を保持
sampling_quality, sampling_warning元の推定の診断。診断不良を理由に評価値を消さない
source_binding, model_contract, evaluated_draws_hash元データ・評定ID、モデル・事前分布・尺度、実際に評価した量の標本との結合

固定値のMCSEが0なのは、モデルがその量を定数と定めているためです。推定の精密さや正しいモデルの保証ではありません。 区間端点のMCSEから被覆判定が確実だとは結論せず、精度閾値もこの関数では適用しません。 MCMCの不確実性と、独立したデータセットの反復に由来する不確実性は別です。 Stanの事後解析の説明も、有限のMCMC標本から 事後要約を推定する際の診断・精度を扱っています。

一つのfit内の人物・項目・チェーン・foldを独立したシミュレーション反復として数えないでください。 既存の parameter_recovery_summary はパラメタ行をまとめる記述的な関数であり、反復間の標準誤差を返しません。 その既存のベクトル真値APIと意味は変更していません。本経路の固定値を含む全行をそのまま旧summaryに渡すことも避けてください。 必要なら coverage_applicable で対象を明示しますが、それでも独立反復の集計にはなりません。

SBCには、分析モデルと整合した同時事前分布からパラメタとデータを生成し、複数データセットで推論手順を 検証する別の設計が必要です。固定した真値での回復評価をSBCとは呼びません （Stan SBC guide）。 本APIは生成過程や独立性を認証できず、generating_truth_verification=:not_established、 independent_replications=:not_verified、sbc=:not_performed を保持します。 次の反復集計はこの評価を再利用します。データ生成・推定・設計間の比較を実行するrunnerは未実装です。

固定した真値でのデータセット間の回復集計

BayesianMGMFRM.recovery_replications は、予定したデータセットの一覧に保存済みの recovery_evaluation を対応させ、量ごとにバイアス・平均絶対誤差・MSE・RMSE・被覆率・平均区間幅を集計します。 同じ量の一つのデータセットを一反復とします。人物・項目・チェーン・fold・他のパラメタの行は反復数に加えません。 比較したい人数・評定割当・分析モデル・事前分布・真値が異なる条件は、別々の scenario_id として集計してください。

using BayesianMGMFRM, Serialization
include("examples/saved_recovery_replications.jl")
# 各ファイルは、そのデータセットの recovery_evaluation を serialize したもの。
summary = saved_recovery_replications(["recovery-D1.jls", "recovery-D2.jls"];
    planned_dataset_ids=["D1", "D2", "D3", "D4"],
    parameters=["theta[P1]"], # 実際の recovery_quantities にある名前を指定
    scenario_id="predeclared-fixed-design-A",
    dataset_independence=(status=:unresolved, evidence="生成手順・seedの独立性は未確認"),
    failures=["D3" => "推定中断"])

この例ではD1・D2を完了、D3を失敗、D4を未記録として残します。予定一覧と対象量は結果を見る前に定めてください。 ファイル名の一覧から予定反復数を逆算すると、失敗を除外した分母になります。 各反復の dataset_id は一意にし、失敗理由を明示します。重複、予定外ID、同じIDの結果と失敗の併記、 変更された評価記録を拒否します。入力順序によらず予定一覧の順に並びます。

出力解釈
ledger完了・失敗・未記録の全予定一覧。完了時の元の評価、診断とMCSEを保持
summaries[i].all_completed対象量を持つ全完了データセットの記述。数値的警告を含む
summaries[i].without_warnings推定診断の警告、対象量のMCSE利用不能、固定値と真値の不一致を除いた記述。精度基準の通過ではない
dispositions対象量ごとの欠損、固定値、警告等。別の量だけを評価した反復も分母から消さない
n_datasets, n_unresolved, n_planned当該集計の使用数、未解決数、予定数。固定された量には回復要約・被覆率を付けない
all_planned_coverage_bounds被覆数をc、使用数をn、予定数をNとすると [c/N, (c+N-n)/N]。未解決の被覆結果をすべて0／1と置いた範囲で、信頼区間ではない

結果は成功・診断状態で選ばれた反復に条件づけられます。警告のない結果だけでよい数値になっても、 予定した設計全体の性能とは結論できません。未解決反復があれば、全予定反復の連続量の性能は利用不能と明示します。 被覆の範囲も計算された区間の0/1判定に関するもので、有限MCMCによる区間端点の誤差は補正しません。

独立なデータセットを同一の生成条件から反復した根拠がある場合に限り、 dataset_independence=(status=:declared_independent, evidence="実際の生成計画・seed規則への参照") を指定します。使用数が2以上なら、反復間SEは各評価値の標本SD（分母n−1）を√nで割ります。 RMSEのSEは SE(MSE)/(2√MSE) の一次近似です。MSEが0ならこの近似SEは missing とし、 被覆率がすべて0／1など経験分散が0の場合も :empirical_zero_variance を付けます。 SEが0という出力を、真の誤差や不確実性がない証拠として使わないでください。 これらは有限反復の不確実性であり、各fitのMCMC MCSEを足し合わせたものではありません。 研究の問い・生成条件・失敗・反復間不確実性を分ける根拠は Morris, White & Crowther (2019)も参照してください。

同じ標本記録、または同じ推定対象と評価標本の組が異なるIDで再利用されていれば、 repeated_evaluation_evidence に残して反復SEを抑制します。これは一部の重複を検出する機能であり、 異なるhashやIDが独立な生成を証明するものではありません。 モデル・事前分布・尺度・区間確率の不一致と、対象量の真値の変化を拒否しますが、 同じ生成過程・評定割当・seed規則を使ったかは入力記録だけでは検証できません。 全パラメタの生成真値も認証しません。量の名前・尺度の対応は利用者の設計で確認する必要があります。 真値を分布から生成するassurance、条件間の対応ある比較、SBC、精度閾値による設計採否はこの関数の対象外です。

比較・診断・保存を一つの手順で確認する

examples/saved_prediction_workflow.jl は、上の5型の保存結果を使い、比較、診断、 パラメタのMCSE、公開レポートの保存・再読込をつなぐ例です。 同じ観測行順で保存されたfitと、それに対応する評定IDのベクトルを渡します。 行順が異なる場合や既存のscalar MFRM/GMFRMを含む場合は、前述の saved_model_comparison と各型のレポート関数を使ってください。

using BayesianMGMFRM
include("examples/saved_prediction_workflow.jl")

analysis = saved_prediction_workflow(
    "Independent" => "normalized.jls",
    "Correlated" => "correlated.jls";
    directory="comparison-reports", # 新しい出力先
    dataset_id="rating-study-v1",
    observation_ids=rating_ids,
    comparison_axis=:model,
)
analysis.comparison.rows
analysis.models[1].diagnostics
analysis.models[1].parameter_mcse
analysis.models[1].report["waic"] # 保存後に読み戻したレポート

出力先をモデル名から作らず model-1、model-2 とし、対応するモデル名は結果に保持します。 保存前に全モデルの比較・診断・レポートを計算するので、入力が未対応の場合は途中までの レポートを残しません。既存の出力先は上書きしません。ファイル書込み中の外部障害まで 全モデルを一括で巻き戻す機能ではありません。

この例の比較指標は :waic または :raw_loo、差のSEは未計算です。 比較に選んだ指標とは別に、各レポートではWAICとraw IS-LOOの両方を要求します。 どちらかを計算できなければ、require_complete=true により保存前に停止します。 モデル名が独立／相関でも、事前分布など他の仕様も違えば「相関だけの効果」とは解釈できません。 各比較行のモデル情報を確認し、警告や判定保留を保持します。推定・図描画は実行しません。
