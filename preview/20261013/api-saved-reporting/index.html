Saved-fit Reporting Candidate API

These qualified candidate functions summarize the eight common saved-fit types. Posterior summaries consume original retained draws and preserve numerical warnings and source identity. The separate observed-score alpha and ICC operations consume ratings and also accept FacetData without a fit. No fitting is performed. Their uncertainty definitions differ: a finite-cohort reliability functional, matched-response score agreement, category use/steps/conditional curves, binary classification risk, and finite-cohort ranks answer distinct questions.

Read the interpretation guide and the saved-fit examples before reporting their values. The standalone functions can also be requested together through fit_report(...; reporting=(...)); see the integrated example below. The ordinary MFRM diagnostics, including the historical replicated-category summary, remain in the Workflow and Diagnostics API.

Reopen an analysis or share its results

Choose the saved format for the task:

TaskSaved format and limitation
Recompute summaries or request another analysis from retained drawsUse save_fit_cache / load_fit_cache in the original Julia and package environment. Keep the Julia version (VERSION), Project.toml and Manifest.toml with the cache. A .jls cache uses Julia's native serialization; package support for two Julia versions does not guarantee that their caches are interchangeable.
Read or share already computed resultsUse save_fit_report_bundle / load_fit_report_bundle. The bundle contains portable JSON reports and tables, with Markdown for reading. It preserves the reported values, warnings and identities; it does not reconstruct a fitted object or supply draws for a new analysis.

For example, a cache written with Julia 1.12 can be rejected by Julia 1.10 with Cannot read stream serialized with a newer version of Julia. Reopen that cache in its original environment and export a report bundle there. Renaming the file does not convert its format. An inability to read this binary cache is separate from the package's ability to run an analysis under Julia 1.10.

One report with explicit analysis choices

The optional reporting named tuple is shared by all eight supported saved-fit types. Omitting it preserves the previous report behavior. Choose sections by supplying category=(...), agreement=(...) and/or a reliability tuple/vector of named cohorts. The optional classification=(;parameters, cutoff, pass_probability, interval=0.90) adds a binary decision section; omitting it preserves the previous report shape. A missing legacy section is :not_requested; no cohort, target or response matching is silently inferred.

Optional alpha=(item="fluency", level=:ordinal, response_ids=performance_ids) adds observed-score alpha with the same dataset/rating identities. It uses no posterior draws and supplies no SE or interval; see its API below.

Optional icc=(item="fluency", model=:two_way_random, definition=:agreement, unit=:single, score_scale=:interval, response_ids=performance_ids) adds intraclass_correlation. It requires a complete response-by-rater rectangle for the selected item and an explicit equal-gap score assumption. There is no silent complete-case deletion. The observed-data section supplies no SE or interval; the existing fit diagnostics remain visible in their own section.

reporting = (;
    dataset_id="assessment-2026", observation_ids=rating_ids,
    category=(;interval=0.99),
    agreement=(;response_ids=performance_ids, interval=0.99, se_unit=:person),
    reliability=[(;id="Ability A", parameters=person_names_A, target=:centered)])

report = fit_report(fit_result; reporting, view=:public,
    include_posterior_predictive=false, include_artifact=false,
    include_waic=false, include_loo=false)
report.category_report.usage_rows
report.posterior_reliability.rows
report.rater_agreement.rows
fit_report_health(report)

save_fit_report_bundle("assessment-report", report; require_complete=true)
restored = load_fit_report_bundle("assessment-report"; require_complete=true)

rating_ids are persistent unique IDs in fitted-row order. performance_ids identify actual shared performances; existing fitted response metadata may be used by omitting that vector. The category and agreement sections share the same dataset/rating identities. When normalized/correlated MGMFRM or multidimensional MFRM reports also request predictive criteria, their top-level dataset_id and observation_ids must match these identities.

person_names_A must contain exact estimated location-coordinate names for one ability dimension. Inspect BayesianMGMFRM.recovery_quantities(fit_result) and choose the cohort deliberately. Add a separate named cohort for another dimension; select target=:absolute or :centered to match the question. Optional normalized weights and the coordinate roster remain in the results. Fixed anchors are not valid members of a reliability cohort.

Each category/agreement options tuple forwards the corresponding standalone API's keywords, except their shared dataset/rating IDs. For example, category options can contain profiles, and agreement options can choose an adjacent-category tolerance. A reliability cohort accepts id, parameters, target and optional weights. All three sections use every original retained draw, regardless of ndraws or draw_indices used for the report's other prediction summaries.

New section names are category_report, posterior_reliability and rater_agreement. The historical ordinary-MFRM category_functioning section keeps its different predictive-replication interpretation and existing defaults. The new flattened rows are intended for tables; result (or reliability results) retains detailed quantities, MCSE, source identities and assumptions. source_result_hash identifies the original standalone API result before report projection. It is not a hash of the projected result; the full report and its public/bundle exports have their own integrity records.

on_section_error=:capture retains section failures and successful neighboring sections. Failed reliability cohorts stay listed alongside successful cohorts. on_section_error=:throw raises the underlying error. require_complete=true rejects captured failures; it does not establish convergence, MCSE adequacy, measurement validity or the availability of every optional quantity. Unknown request keys, inconsistent IDs and ambiguous cohort names fail before reporting. Sampling, numerical, category-review and no-overlap warnings remain visible in Markdown and table/JSON exports. No new model fitting is performed.

Finite-cohort posterior reliability

BayesianMGMFRM.posterior_reliability — Function
BayesianMGMFRM.posterior_reliability(fit; parameters, target, weights=nothing)

Summarize finite-cohort posterior reliability from an existing supported fit. Select at least two estimated location coordinates by exact names from recovery_quantities(fit), all in the same person/item/rater block and dimension. Fixed anchors, loadings, thresholds and mixed dimensions are rejected. Optional positive weights follow parameters order and are normalized to sum to one; the default gives each selected level equal weight, not each observed rating.

The required target=:absolute uses locations in the fitted coordinate system. target=:centered subtracts the selected cohort's weighted mean within each joint draw, retaining covariance and removing common-location uncertainty. Subset selection and weights therefore define both the cohort and its reference.

For selected means mᵢ, posterior variances vᵢ, and normalized weights wᵢ, return B = sum(wᵢ*(mᵢ-sum(wⱼ*mⱼ))^2), W = sum(wᵢ*vᵢ) and B/(B+W). This is the between-level fraction of variance of a weighted mixture of the selected posterior marginals. Both level and retained-draw moments use normalized probability weights (no Bessel correction). It is a posterior functional estimated by pooled complete chains, not a distribution of reliability over draws. No CrI, FACETS separation/Strata, population, retest or new-design reliability is inferred. Zero total variance returns missing; empirical zero posterior variance is flagged, never treated as proof that the sampler resolved a parameter exactly.

mcse uses the first-order influence of the ratio with the existing chain-aware asymptotic-variance estimator. It is numerical error, not a credible interval. It is unavailable at zero between/within variance, for short/single chains or degenerate influence. Finite-draw bias and convergence are not certified by MCSE. Sampling warnings, exact selected coordinates, model/prior identity and source hash status are retained. Shared calibration uncertainty is included only to the extent represented in the saved joint draws; fixed calibration cannot be restored. High rater reliability means distinguishable severity, not score agreement.

This qualified candidate entry supports the eight common saved-fit types and preserves each model's support limits. It does not replace the historical separation_reliability_summary numerically or validate its old interpretation.

Common-response score agreement

BayesianMGMFRM.rater_agreement — Function
BayesianMGMFRM.rater_agreement(fit; dataset_id, observation_ids,
    response_ids=nothing, interval=0.95, adjacent=1, se_unit=:none,
    max_prediction_cells=20_000_000, max_rater_pairs=10_000)

Compare observed and model-expected agreement for the same response and item. Uses the eight common saved-fit types, all original retained draws and category probabilities. Supply unique rating observation_ids in fitted-row order and globally unique response identities through fitted response_id metadata or an explicit response_ids vector (nonempty strings or integers). Repeated response IDs across raters/items are expected; one ID must belong to one person and one combination of all recorded optional metadata. Supplied and fitted IDs must agree. Duplicate response-item-rater rows are rejected. Matching by person-item alone is never inferred, and omitted context cannot be verified from the scores.

Return overall, per-rater and every unordered fitted-rater-pair row, retaining zero-overlap rows and unpaired observation IDs. Each common response-item and unordered rater pair contributes one opportunity. Overall weights are equal per opportunity, not per person, response or rater pair. Per-rater totals count its incident opportunities, so their denominators sum to twice the overall denominator. The opportunity ledger preserves both rating IDs and the response/item/person.

exact uses the original category labels. adjacent includes exact agreement and categories at most the declared number of ordinal positions apart. It does not realign a rater's lowest observed PCM category as some FACETS reports do. For each joint posterior draw, expected exact agreement is sum_k p_A(k)*p_B(k); adjacent agreement sums the corresponding category pairs. Conditional independence is assumed given that draw. Averaging separately by rater before multiplying would lose shared-parameter dependence and is not used.

Intervals are central posterior intervals for the conditional expected rate on these fitted responses and raters, not posterior predictive intervals for realized agreement, population CIs or evidence for a dependence mechanism. The mean observed-minus-expected discrepancy is descriptive, not a p-value. MCMC MCSE for expected means/quantiles is reported separately; short/degenerate draws retain unavailable status. If the tolerance spans the whole category scale, the adjacent probability is structurally one and labeled accordingly.

se_unit=:person optionally adds a ratio-linearization SE for observed rates with independent, exchangeable person clusters, preserving all within-person opportunities together. It conditions on these raters/items and does not handle arbitrary crossed dependence or sampling-design weights. Default :none reports no observed-rate SE. Fewer than two persons is unavailable; zero empirical cluster variance is flagged. No observed CI, kappa, automatic cutoff or reliability correction is computed. Resource limits reject oversized extraction/rosters before allocating the predictions; they do not subsample or omit pairs.

Observed-score Krippendorff alpha

BayesianMGMFRM.krippendorff_alpha — Function
BayesianMGMFRM.krippendorff_alpha(data::FacetData; item, level,
    dataset_id, observation_ids, response_ids=nothing,
    max_category_pairs=1_000_000)

Compute observed-score Krippendorff alpha for one explicitly selected item (use its label, not its index). level is required: :nominal or :ordinal. No model fit or posterior draws are used. Integer category codes and their order come from data.category_levels; nominal codes are labels, not distances. Ordinal distances use pairable category frequencies, not squared score gaps.

Unique rating IDs are in data-row order. Supply globally unique response IDs explicitly or through response_id metadata, as in rater_agreement. A response must identify the same person and recorded context. Duplicate response-item-rater rows are rejected; repeated occasions need separate response IDs. Items are never pooled. This checks recorded identity, not construct validity.

Missing ratings are absent rows (FacetData rejects literal missing scores). Units with one rating are listed but excluded from both disagreements and the category margins. Entirely unobserved units cannot be counted from these data. Each usable unit with m ratings contributes its ordered pairs weighted by 1/(m-1), giving total coincidence mass m, rather than equal weight per pair. Returns alpha, observed/expected disagreement, coincidence/distance matrices, marginal counts and a unit ledger with included, singleton and other-item IDs. Zero expected disagreement and no pairable units yield missing with distinct statuses. Negative alpha is retained; no cutoff or clipping is applied.

The result is descriptive: no confidence/credible interval, SE, bootstrap, missingness correction, severity adjustment, ICC or population guarantee. Ordinal distance matrices are specific to these pairable marginal frequencies. max_category_pairs bounds each dense K-by-K matrix before allocation; there is no dense rater-pair roster. Use fit_report(...; reporting=(dataset_id=..., observation_ids=..., alpha=(item=..., level=:ordinal, response_ids=...))) to include this observed-data result in existing report bundles.

Reference: Krippendorff, Computing Krippendorff's Alpha-Reliability (2011, literature updated 2013), sections C and D.

This operation takes FacetData and needs no fit. In an existing fit report, request reporting=(dataset_id="study", observation_ids=rating_ids, alpha=(item="fluency", level=:ordinal, response_ids=response_ids)). The optional krippendorff_alpha section preserves observed disagreement, expected disagreement, category margins and excluded singleton IDs through public JSON/Markdown/table bundles. Omission leaves existing report fields unchanged. Its descriptive status does not certify the fitted model.

Owner-aware category functioning

BayesianMGMFRM.category_report — Function
BayesianMGMFRM.category_report(fit; dataset_id, observation_ids,
    interval=0.95, min_count=5, min_proportion=0.01,
    order_probability_threshold=0.8, profiles=(),
    max_prediction_cells=20_000_000, max_curve_cells=20_000_000)

Summarize category use and correctly owned steps across the eight common saved-fit types, using every original retained draw. Supply persistent, unique rating IDs in fitted-row order. Canonical fixed-MFRM records are required. No fitting, response simulation, category sorting/collapse or random draw selection occurs.

usage_rows retain every declared category overall, per item and per rater, observed counts/denominators, actual contributing threshold groups and the posterior distribution of the conditional expected proportion. Counts give equal weight to ratings, not persons, raters or likelihood/survey weights. This is the observed allocation, not balanced standardization. Its intervals are not predictive intervals for realized category use; a discrepancy is not a p-value. The existing MFRM category_functioning_summary keeps its predictive-replication semantics and unchanged numerical implementation.

threshold_rows identify shared, item- or rater-owned centered transitions, excluding dummy reference-category zeros. They include posterior SD, equal-tailed intervals, joint-draw ordering probabilities, gap summaries and chain-aware MCSE. Posterior SD is not a repeated-sampling SE; empirical constant draws/indicators are not automatically treated as structural constants or certain ordering. Flags prompt review and never establish a reason to merge categories.

Optional profiles are named tuples with unique string id, exact stored item and rater labels, dimension (index or label), strictly increasing finite ability_grid, and fixed_abilities=Dict(other_dimension=>value, ...) specifying ALL other dimensions. Profiles are slices, not integrations over other abilities or raters. curve_rows give conditional category probabilities at the grid points; crossing_rows give draw-wise ability values where adjacent categories are equally probable. These probabilities need not each be 0.5. Steps, crossings and expected- score half-points differ. Inactive dimensions retain flat curves and no unique crossing. The scalar GMFRM's item coefficient multiplies the whole contrast, whereas MGMFRM loadings multiply abilities; native scale conventions are retained.

All intervals are pointwise, conditional on this fitted model and its calibration policy; they are not simultaneous bands, new-rater guarantees or calibration evidence. Fixed anchors omit external calibration uncertainty. A profile grid is a display choice, not evidence of empirical support. Structural constants and unavailable numerical summaries stay explicit. Sampling warnings, source identity, model/step contracts, complete chain layout and a content seal are retained. Resources exceeding the explicit budgets fail instead of subsampling. This qualified candidate API is also available through the optional fit_report(...; reporting=(; category=(...), ...)) request.

Conditional ability precision and classification

BayesianMGMFRM.posterior_classification — Function
BayesianMGMFRM.posterior_classification(fit; parameters, cutoff,
    pass_probability, interval=0.90)

Report conditional ability precision and binary classification risk from saved joint draws. parameters selects one or more distinct estimated person locations by exact names from recovery_quantities(fit), in one dimension and scale. Fixed anchors, other facets and mixed dimensions are rejected. The finite cohort is exactly these people, each counted once, independent of their rating counts.

Both rules are required: qualification means ability >= cutoff in the fitted coordinate system; classify a person as :pass when the saved estimate of that probability is >= pass_probability (strictly between zero and one). Equality belongs to the qualifying/passing side. The package does not choose a substantive standard or infer loss costs. No centering, scale linking or multidimensional composite is performed. For dimensions with different interpretations, call separately with justified cutoffs; these calls do not define a conjunctive rule.

Each row retains posterior mean/SD, pointwise equal-tailed CrI (interval=0.99 requests 99%), probability of qualification, the specified decision and its posterior error probability. SD describes uncertainty conditional on this model, prior, data and calibration; it is not repeated-sampling SE or MCMC error. cohort reports expected false-pass/false-fail/total counts and the probability of any error, calculated within each joint draw to retain posterior dependence. Decisions are held fixed at the reported choices for these calculations.

Mean MCSE accounts for chain autocorrelation. Short/single chains and constant sampled events have unavailable MCSE, not proof of certainty. A count is known zero only when the decision rule leaves no people eligible for that error type. Inspect event MCSE and convergence before interpreting decisions near the chosen probability boundary; no precision threshold or automatic refit is applied. The reported MCSE conditions on the displayed decisions and does not quantify their possible changes across finite MCMC runs.

These are posterior risks for the selected people, not known-truth error rates, population sensitivity/specificity, future-score predictions or design guarantees. Shared calibration uncertainty is included only where represented in the joint draws. Source identity and sampling warnings are preserved for all eight common fit types. This qualified candidate is not statistical acceptance of a model.

To include this result in the same public report and bundle, add classification=(;parameters=person_names_A, cutoff=study_cutoff, pass_probability=study_probability_rule, interval=0.99) to reporting. It needs no observation IDs of its own. posterior_classification.rows contains individual results and posterior_classification.cohort_rows contains the four cohort summaries; both are exported as tables. This option also works in each model's reporting_by_model entry in saved_prediction_workflow. The required rules must be justified on each model's fitted ability scale; sharing their numeric values across models does not establish scale equivalence.

Invalid coordinates/rules follow the same section-error and require_complete policies as other reports. Captured errors remain errors on public export and reload. Read the decision interpretation before presenting a probability as evidence for a pass/fail decision.

Finite-cohort posterior ranking

BayesianMGMFRM.posterior_ranking — Function
BayesianMGMFRM.posterior_ranking(fit; parameters, direction,
    top_k=nothing, interval=0.90, max_rank_cells=20_000_000)

Summarize posterior ranks of an explicit finite cohort from saved joint draws. Select at least two distinct estimated person coordinates by exact names from recovery_quantities(fit), in one ability dimension and scale. Fixed anchors, other facets and mixed dimensions are rejected. direction=:higher puts the largest value first; :lower puts the smallest first. Rank 1 is always first. No direction, composite ability, population or selected winner is inferred.

Rank people within each original retained draw, preserving posterior dependence. Exact numeric ties receive the average of their occupied positions (midrank). Each row reports mean rank and its chain-aware MCSE, rank SD, median and a pointwise equal-tailed interval (interval=0.99 requests 99%). Interval endpoints use the empirical inverse CDF without interpolation, so belong to the observed rank support. They need not enclose exactly the requested mass, especially with ties or few draws. These are marginal rank intervals, not a simultaneous ordering or a credible interval for the mean rank. Interval/quantile MCSE is not computed.

Optional top_k is an integer from 1 to the cohort size. top_k_probability contains lower, upper and boundary_tie_probability summaries, each with a posterior mean and numerical MCSE. A person's best position is one plus the number strictly ahead; their worst position includes all equals. The lower probability counts draws with worst position <= k; the upper counts draws with best position <= k. The difference is the probability of a tie crossing the selection boundary. These are bounds over unspecified tie-breaking rules, not a credible interval. With no boundary ties they coincide. No random tie-breaking or arbitrary input-order preference is introduced. top_k == n_people is the structural event that everyone is included, with probability one and MCSE zero.

Mean MCSE reuses the classification report's autocorrelation-aware estimator. Constant sampled ranks/events and short/single chains retain unavailable MCSE, not certainty. Diagnostics and source identity remain attached. Ranks depend on the selected cohort; they discard the magnitude of ability differences and are not ranks of posterior means, future-score ranks, practical-equivalence tests, known-truth rank recovery or calibrated selection guarantees. No all-pairs matrix, whole-order probability or multidimensional aggregate is computed.

The algorithm uses O(draws * people * log(people)) sorting and O(draws * people) working storage. max_rank_cells bounds the selected draw-by-person matrix before allocation; it is not a bound on the already loaded fit's memory. This qualified candidate supports the eight common saved-fit types without refitting and does not establish their scientific acceptance.

Add ranking=(;parameters=person_names_A, direction=:higher, top_k=3, interval=0.99) to reporting for a cohort with at least three people. posterior_ranking.rows exports each person's rank summary and top-k probability bounds, with cohort size, direction, interval and tie policy included in the table. Full MCSE/status details, diagnostics and source identity remain in posterior_ranking.result. The same request works in the per-model reporting_by_model entries of saved_prediction_workflow.

Omitting ranking or supplying nothing preserves the preceding report shape. An invalid cohort or exceeded max_rank_cells follows the existing captured-error and require_complete policy. A complete report still may contain unavailable MCSE. The ranking interpretation guide explains pointwise intervals, cohort dependence, ties and what ranks omit.

Observed-score intraclass correlation

icc = BayesianMGMFRM.intraclass_correlation(data;
    item="fluency", model=:two_way_random, definition=:agreement,
    unit=:single, score_scale=:interval,
    dataset_id="assessment-2026", observation_ids=rating_ids,
    response_ids=performance_ids)
icc.icc
icc.status
icc.anova_rows
icc.unit_rows

Here N is the number of response units, K the number of raters, and MS_response, MS_rater and MS_error are the two-way ANOVA mean squares. The numerator in all four point formulas is MS_response - MS_error:

Definition and unitDenominator
Agreement, singleMS_response + (K-1)*MS_error + K*(MS_rater-MS_error)/N
Agreement, averageMS_response + (MS_rater-MS_error)/N
Consistency, singleMS_response + (K-1)*MS_error
Consistency, averageMS_response

The residual combines response-by-rater interaction and measurement error; with one rating per cell these components cannot be separated. Negative component differences are not set to zero. A negative ICC with a positive denominator is retained; a zero or negative denominator returns missing ICC with a distinct status, retaining any finite raw_ratio for inspection. That raw ratio is not an admissible reliability result. Constant scores everywhere therefore do not produce an informative coefficient. Near-zero denominators can make ratios unstable; inspect the ANOVA table rather than interpreting a cutoff mechanically.

BayesianMGMFRM.intraclass_correlation — Function
BayesianMGMFRM.intraclass_correlation(data::FacetData; item, model,
    definition, unit, score_scale, dataset_id, observation_ids,
    response_ids=nothing)

Compute a two-way ANOVA, observed-score ICC for one explicit item label and a complete response-by-rater rectangle. Every response must have exactly one rating from the same set of at least two raters; at least two responses are required. Incomplete designs are rejected, without deletion or imputation. Response/rating identities follow rater_agreement. Items are not pooled.

All choices are required. model=:two_way_random treats raters as a sample from a rater population; :two_way_mixed targets this fixed panel. definition is :agreement (systematic rater differences count) or :consistency (additive rater differences are removed). unit=:single concerns one rating; :average concerns the arithmetic mean of all K recorded raters. The model choice changes generalization, not the formula for a given definition/unit.

score_scale=:interval explicitly declares that equal gaps between the integer score codes have substantive meaning. This is a user assumption, not a property established by FacetData or the ICC. Nominal/ordinal scale choices are rejected; consider krippendorff_alpha for nominal/ordinal agreement instead.

Return the coefficient, numerator/denominator, ANOVA sums of squares, degrees of freedom and mean squares, response/rater ledger and identities. Negative values with a positive denominator are retained, not clipped. A nonpositive denominator yields missing with an explicit status; any finite raw ratio is retained for inspection, not interpreted as reliability. Repeated responses from one person are counted and disclosed; there is no independence or population guarantee.

This is an unadjusted observed-score method-of-moments point estimate, independent of model draws. No SE, confidence/credible interval, significance test, one-way ICC, missing-data mixed model or latent-trait reliability is provided. Fit-report integration uses reporting=(dataset_id=..., observation_ids=..., icc=(item=..., model=:two_way_random, definition=:agreement, unit=:single, score_scale=:interval, response_ids=...)). No MCMC is run.

References: Shrout & Fleiss (1979), doi:10.1037/0033-2909.86.2.420; Liljequist et al. (2019), doi:10.1371/journal.pone.0219854; the psych package ICC documentation for the McGraw-Wong random/mixed interpretation.
