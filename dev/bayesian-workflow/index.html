Bayesian Workflow

Unreleased documentation preview — 13 October 2026

This manual includes unreleased interfaces and examples. It is not the documentation of an installed release. Model support and scientific acceptance remain as stated on each page.

A many-facet analysis is more than a sampling call. The rating design, identification constraints, priors, sampler behavior, predictive performance, and reporting scope all affect what can be interpreted.

Follow one analysis through the APIs

Keep one question in view: is R2 more severe than R1 after accounting for the people and tasks they rated? The first analysis already implements this workflow. The steps below expose its connections; they are an alternative way to run the same example, not another fit to perform after FirstMFRMAnalysis.main().

The table uses the stable one-dimensional MFRM route. The unified lifecycle verbs (design_summary, contract, qualify, posterior_summary, facet_summary, category_summary, contrast, predictive_check, criteria, prior_sensitivity, save_fit / load_fit, and save_report / load_report) also dispatch across experimental families while preserving each model's specific result type and contract(x) boundary; use the model entry points below and operation support table before changing the route. A common function name does not make all model/prior combinations interchangeable.

Prepare and inspect without estimating

using BayesianMGMFRM
include(joinpath(pkgdir(BayesianMGMFRM), "examples", "first_analysis.jl"))
prepared = FirstMFRMAnalysis.inputs()
prepared.spec
model_equation(prepared.spec)
constraint_table(prepared.spec)

prepared contains data, spec, prior and controls. The shipped example's inputs() helper reads 72 fixed artificial ratings and calls FacetData, validate_design and mfrm_spec; it does not fit or generate ratings. R1 is the zero-severity reference, so rater[R2] represents R2−R1 in this example. For your own data, replace this preparation with the CSV/data workflow, choose the model and check its prior implications. The teaching settings are not a sample-size or prior recommendation.

Fit once and preserve the result

This block runs four chains. If you already have the matching saved fit, skip it and use the reopening block below.

out = mktempdir(mkpath("results/connected-analysis"); cleanup=false)
fitted = fit(prepared.spec; prior=prepared.prior, prepared.controls...)
cache_path = joinpath(out, "fit.jls")
save_fit_cache(cache_path, fitted)

The new directory keeps earlier attempts intact. Save before optional reports or figures so a later reporting failure can be handled from completed draws. This cache does not resume an interrupted sampler. Keep the input, analysis script, exact package source, Julia version and dependency environment with it. See sampling progress to monitor a new fit; monitoring does not establish convergence or change the selected model.

Turn the same fit into an answer

answer = FirstMFRMAnalysis.result(fitted, prepared)
answer.numerically_qualified
answer.interpretation

This existing teaching helper uses diagnostics, posterior_summary and posterior_mcse on that same fitted object. It checks the data/model/prior identity, combines global diagnostics with the R2−R1 mean and interval-endpoint MCSE limits, and withholds interpretation when those conditions fail. The helper's 90% interval and computational limits belong to this example; define your own estimand and reporting precision before a new analysis. Use the walkthrough to read the stored estimates, MCSE and sampler warnings. An interval containing zero does not establish equivalence, and a precise contrast does not establish model fit.

Reopen without another fit

restored = load_fit_cache(cache_path)
reopened_answer = FirstMFRMAnalysis.result(restored, prepared)

In a later session, load the same example definitions and preparation in the original environment, and set cache_path to the saved file. If you only need an already exported answer, read its text/JSON or a portable report bundle; those files do not reconstruct draws for a new contrast. The example's main(["--saved-fit", path]) mode writes the answer into a new folder without refitting.

Know which operations do more work

Operation on an existing analysisNew posterior fit?What happens
Summaries, diagnostics, MCSE, interval/chain figuresNoReuse retained draws; calculations can still be expensive. They do not remove existing warnings.
Conditional posterior predictive checks or plot_predictiveNoGenerate replicated outcomes unless explicitly consuming saved predictions. Record the seed, draw count and prediction target; consider the size of requested arrays.
Different priors, anchors, slopes, dimensions or an estimated effectYes, for a new posterior analysisA changed model/specification cannot be attached to the old fitted object. A label or plot change is not a sensitivity analysis.
Portable saved-report readerNoRead computed values and warnings; it cannot recompute intervals, generate predictions or migrate a native cache.

When numerical checks fail, keep the fit and identify the affected quantity or stage. When predictive fit is poor, limit the substantive claim or justify a model change. When reporting alone fails, repair that stage and reopen the saved fit. These are different decisions; none calls for silently repeating the same fit until a preferred result appears. The remaining sections explain each decision and link to the corresponding function help.

For rater decisions, use the evidence-to-conclusion guide to distinguish a fitted group/item contrast, residual screen, predictive discrepancy, prior sensitivity and fairness claim. It also separates the available drift workflow from research-only halo classification.

1. Validate the Rating Design

Create FacetData from long-format ratings and run validate_design. Review:

  • person, rater, item, and category coverage;
  • disconnected or weakly linked rating blocks;
  • skipped or sparse categories;
  • repeated ratings and optional time or order fields;
  • anchors and optional grouping variables;
  • the distinction between planned and accidental missingness.

coverage_summary, coverage_matrix, rater_overlap, anchor_linking_summary, and rating_design_check provide additional review rows. These checks do not make non-random rater assignment ignorable. The current optional occasion column is categorical metadata; it does not by itself encode exact within-rater order, timestamps, active duration, or randomized presentation. Likewise, declared parameter anchors and rater-linking summaries are not the same as controlled benchmark responses deliberately distributed across a rating sequence. Time-varying severity, fatigue, or learning claims therefore require a separate process-data and temporal-identification design.

If ratings share an answer, prompt, or item cluster, record response_id and testlet_id separately and run testlet_design_check. The check keeps ordinary rating-graph connectivity separate from person-by-testlet, rater-by-response, rater-by-task, and fixed-Q dimension support. Passing it establishes only conservative structural eligibility for a candidate that is not currently fit-supported, not the presence or interpretation of a clustered effect. Custom thresholds are explicitly marked unvalidated.

2. Inspect the Model Before Fitting

State the estimand first: for example, an ability difference within a named dimension, a rater-severity contrast, or predicted category proportions for a specified rating design. This determines which model assumptions, summaries, and precision checks matter. Use the model comparison to distinguish fixed coefficients from estimated loadings and fixed from estimated ability correlation.

Create an mfrm_spec and inspect:

  • model_equation for the likelihood and source contract;
  • constraint_table and identification_declarations for the gauge and reference rules;
  • optionally, getdesign for the identified parameter vector;
  • model_manifest for a portable summary of data, model, and design.

For stable one-dimensional MFRM, call fit(spec) when no separate design inspection is needed. Multidimensional MFRM and GMFRM/MGMFRM use BayesianMGMFRM.Experimental.fit(spec). An estimated correlation requires BayesianMGMFRM.Experimental.correlated(spec) first, within the documented two-dimensional restrictions. Specified configurations are not necessarily fit-supported. The support table in Scope and Releases governs whether a fitting call is available.

Look for implausible score distributions, category use, or facet ranges before inspecting the observed-data posterior. GeneralizedPrior SDs describe its independent free-coordinate normals, including log-loadings and log-consistencies, not the positive transformed parameters. In contrast, NormalizedMGMFRMPrior uses kernel SDs for centered rater/step blocks; these are not their free-coordinate or full-vector marginal SDs. MeanProfilePrior(units=:unit_logit) converts means, not base-prior SDs. See free and constrained prior densities before transferring numeric widths between these routes. person_sd fixes the marginal ability prior scale; it is not an estimated hyperparameter. The experimental prior check exposes raw/direct draws, replicated scores, and implication warnings. See prior conventions before choosing scales or comparing them across models. Posterior sensitivity requires actual refits under defensible alternatives; repeatedly summarizing one saved fit does not evaluate it.

4. Fit and Diagnose

Use the fitting entry point for the selected model above. Set an integer seed when replay is required and record the sampler controls. Multiple chains are required for meaningful between-chain convergence checks.

Review:

  • sampler_diagnostics for chain and HMC behavior;
  • mcmc_diagnostics for R-hat and ESS;
  • parameter_block_diagnostics for block-level patterns;
  • diagnostics for the compact combined status.

The primary convergence fields are rank-normalized split R-hat, bulk ESS, and tail ESS. The historical rhat and ess fields remain available for compatibility. Use the rank-normalized fields for convergence review; at least two independent chains and enough finite, nondegenerate draws are required.

For guarded GMFRM/MGMFRM fits, inspect both raw unconstrained and direct constrained parameter rows: the gate fails if either applicable surface fails. A constrained coordinate fixed by a transform with zero raw dimension stays in the output with diagnostic_status = :structurally_fixed, flag = :structurally_fixed, and quality_gate_applicable = false. It is not used in extrema or failure counts. This exception does not apply to a reconstructed constrained coordinate that varies with free raw coordinates; that coordinate remains gated. The versioned diagnostic contract is part of generalized cache identity, so a cache written under the older provisional contract cannot silently supply a modern diagnostic status.

The sampler summary also reports E-BFMI availability for every expected chain. An unavailable energy diagnostic is missing evidence, not a passing check. Use sampler_diagnostics(fit_result; phase = :warmup) to inspect recorded AdvancedHMC or CmdStan adaptation events separately from retained posterior diagnostics.

A completed run is not automatically a trustworthy run. Divergences, tree-depth saturation, low ESS, unstable R-hat, non-finite evaluations, or constraint failures require investigation.

After that convergence review, use posterior_mcse to quantify the simulation error of reported means, standard deviations, and quantiles:

mcse_rows = posterior_mcse(fit_result;
    probabilities = (0.025, 0.5, 0.975),
)

For GMFRM/MGMFRM, BayesianMGMFRM.direct_posterior_summary and the default posterior_mcse summarize transformed model parameters. posterior_summary instead summarizes their raw coordinates, so match parameter names and scales before comparing intervals and MCSE. A credible interval describes parameter uncertainty conditional on the model and data; MCSE describes numerical uncertainty in an estimated posterior summary. A small MCSE does not imply a narrow credible interval, correct model assumptions, or accurate measurement.

For fixed-coefficient multidimensional MFRM, this call also supports correlated abilities and either rater prior, including reloaded fits from either backend. It reports reconstructed parameters and rho on their model scales by default; see multidimensional precision summaries for coordinate selection and fixed/short-chain statuses.

For a derived estimand, compute one value per posterior draw while preserving the contiguous chain blocks, place the values in matrix columns, and call the matrix method with chains and parameter_names. The function deliberately does not turn MCSE into a universal pass/fail threshold. Required precision depends on the reported estimand and substantive decision; MCSE also cannot repair or certify non-converged chains. The saved-fit contrast example implements this calculation for within-dimension ability differences, rater severity differences and log-consistency ratios, including optional practical ranges and the simulation error of their posterior probabilities.

For independent fixed-Q MGMFRM, optionally inspect diagnostics(fit_result; include_location = true) for common ability/item location movement. Its location rows supplement the original diagnostic assessment and are not automatically included in the ordinary report. The saved-fit walkthrough shows these checks, intervals and MCSE together without sampling again.

Qualification and focal precision

Use the same convergence controls across supported qualify methods:

gate = qualify(fit_result; max_rhat=1.01, min_ess=400.0, min_bfmi=0.3)

Interpret the returned flag within its stated scope:

ResultMeaning of a passing gatePrecision still to assess
Common fit or supported Experimental NamedTuplequalified: whole-fit parameter diagnostics and complete sampler telemetry, under requested thresholds. focal_precision_qualification=:not_assessed.MCSE of the means, interval endpoints, contrasts, decisions and probabilities used in the analysis.
Starresult.numerically_qualified: raw/transformed diagnostics, complete sampler telemetry and the named result.focal_parameters pass. The focal quantities are finite-entity root/branch correlations, with mean and 95% interval-endpoint MCSE limits.Other population correlations, residual-association parameters, contrasts, ranks, event probabilities and any different interval endpoints.

For Star, rhat_max, ess_min, and ebfmi_min remain aliases of the common controls; supplying both spellings for one control is an error. Its check_transformed=false option returns a partial diagnostic report: transformed_assessed=false, transformed_passed=missing, and both whole-fit and overall qualification are false. Missing, duplicate or misordered retained sampler records cannot pass the telemetry gate. This avoids interpreting an unperformed check as successful. Previously stored warnings remain attached even if a user chooses looser thresholds for a new diagnostic report.

The thresholds are numerical criteria, not a scientific adequacy test or a universal precision recommendation. Assess MCSE in the estimand's own units and at the endpoints you report. The posterior quantile-MCSE documentation explains why quantile uncertainty is a separate calculation and can be unavailable for constant or nonfinite chains. A constant estimated event indicator does not establish a zero probability. Preserve unavailable precision and model-fit or prior-sensitivity warnings.

5. Examine Predictions and Residuals

Use posterior_predictive_check, predictive_check_summary, and calibration_table to compare observed and replicated outcomes. predictive_residuals, predictive_standardized_residuals, residual_summary, fit_stats, and rater_diagnostics help locate misfit.

The generalized posterior predictions replicate the existing rating rows using the fitted persons, items, and raters. Agreement checks conditional model fit; it does not measure held-out accuracy or prediction for a new person, item, or rater. A category-proportion plot also cannot establish parameter recovery or interval coverage. Those questions need their own design and evidence.

predictive_standardized_residuals reports draw-specific Pearson residuals and explicitly excludes rows with negligible predictive variance. Non-finite predictions are errors, not low-variance exclusions. This is a low-level input, not a test of local independence. The provisional local_dependence_contract separates single-rating item pairs, within-rater item pairs, and rater pairs; fixes draw-specific support, duplicate rejection, weighting, paired predictive tails, and multiplicity scopes; stratifies estimation by testlet; and forbids implicit rater aggregation or cross-rater cross-item pairing. Its decision labels remain disabled until known-truth calibration.

When response_id and testlet_id are declared, use local_dependence_summary for the corresponding report-only pair summaries:

ld = local_dependence_summary(fit_result)

The function selects distinct posterior draws, generates one conditional replicated dataset from each selected draw, and applies the same matching and validity rules to observed and replicated standardized residuals. It keeps single-rater item pairs, within-rater item pairs, and rater pairs on the same response and criterion separate. Criterion-split scoring is not silently relabelled as single-rater Q3, and applicability is evaluated separately in each testlet so one criterion-split stratum does not suppress another valid single-rating stratum. Sparse or undefined pairs with at least one common unit remain structured pair rows with missing evidence values; zero-overlap combinations remain visible in family counts and testlet support graphs. Family-wide and testlet-specific support statuses are reported separately. Before large work or allocations, the API counts candidate-pair rows, shared-unit links, positive-pair-by-draw cells, pair/common-unit-by-draw cells, and draw-by-observation-by-category cells. Posterior predictive tail fractions, BH-adjusted values, and the all-family maximum statistic are calibration-pending references; none is a decision label or evidence for a specific mechanism.

These local-dependence summaries are uncalibrated diagnostic references. They provide no decision threshold or mechanism classification and do not make clustered effects available for fitting. The separate research helpers are documented in the Validation and Evidence API; running a simulation study is not a prerequisite for an ordinary analysis.

Observation-row LOO does not validate prediction for a wholly unseen response whose shared effect was informed by other rows from that response.

DFF rows are screening information unless the fitted model explicitly supports the corresponding identified effect. Statistical differences should be reported separately from practical magnitude and substantive interpretation.

For figures without assembling draw matrices, load CairoMakie and use:

BayesianMGMFRM.plot_posterior(fit_result; block = :rater)
BayesianMGMFRM.plot_diagnostics(fit_result; block = :rater)
BayesianMGMFRM.plot_predictive(fit_result; ndraws = 200, seed = 42)

The first shows parameter uncertainty, the second retained-chain behavior, and the third category proportions under conditional replications of the fitted rows. BayesianMGMFRM.plot_wright(fit_result) additionally displays the stable MFRM measures and item-step boundaries on a shared logit scale. Generalized fits require dimension/scale interpretation and do not support a Wright map. See figures and export.

6. Compare Models Carefully

Use compare_models for the supported comparison routes. For a CriterionCollapse fit, compare_models(result) compares the all-ordinary and at-least-one-collapse submodels under their induced priors. This is model evidence rather than WAIC/LOO; pair it with the joint count check to assess the selected category pattern. State the prediction unit and baseline before reading a difference. Paired ELPD differences require the same observed outcomes; see the loo comparison documentation. A matching row count alone does not establish compatibility.

For the eight common MFRM/GMFRM/MGMFRM result types, use named pairs and an explicit comparison axis:

comparison = compare_models("reference" => reference_fit, "alternative" => alternative_fit;
    comparison_axis=:model, dataset_id="ratings-v1", observation_ids=rating_ids,
    criterion=:waic, baseline="reference", se_unit=:none)
comparison.rows                # input order; each difference is model minus reference
comparison.criterion_target    # one rating omitted, fixed specification
comparison.uncertainty         # uncomputed MCSE/SE remain explicit

rating_ids supplies one unique string per original rating. If fit row orders differ, use a dictionary from the same model names to each fit's ID vector. Use comparison_axis=:dimensions when D/Q may differ, or :q_matrix for Q changes at fixed D. These operations reuse compare_predictions; its data, category, conditioning and draw-layout checks remain. They use all retained draws. Model identity, prior/scale information and warnings remain in each row; a comparison axis does not isolate a causal effect of that choice.

For Star fits, the model already retains event IDs:

comparison = compare_models("association" => association_fit,
                            "no_residual_association" => no_residual_fit)
comparison.primary_name
comparison.baseline_name
comparison.waic_diff.elpd_diff
comparison.psis_loo_diff.interpretation_scope

This route accepts exactly two Star results and returns primary minus baseline, without choosing a winner. It aligns events by ID and checks actual entity/rater labels, scores, criterion IDs, category supports and scoring directions. Priors, root choice and dependence terms can differ. In the include_phi=false alternative, only residual association is removed; entity/rater correlations remain estimated. Do not reuse event IDs for different measurements. Current in-memory Star criteria(fit) results can also be compared with compare_models(primary_criteria, baseline_criteria; names=("a", "b")). Older reports lacking observed-event bindings remain readable but cannot establish this comparison contract. Portable JSON remains a computed report, not an in-memory criteria object. Preserve it and its original producing environment; this is not a native-cache migration facility or a request to refit.

Without draw-selection controls, common-fit probability arrays preserve the original joint draw order. ndraws resamples with replacement; draw_indices preserves the requested order and duplicates. These probability summaries are not replicated outcomes. predictive_check generates outcomes where supported, so it is a distinct operation. Inspect pointwise influence, Pareto-k and numerical warnings before interpreting any comparison; a ranking alone is not a superiority claim.

Sensitivity work should cover defensible prior choices and any threshold, anchor, dimensionality, or Q-matrix decisions that could change the interpretation.

7. Report the Boundary

posterior_summary, fair_average_summary, separation_reliability_summary, wright_map_data, and other reporting helpers return table-oriented results where the chosen model supports them. In particular, the stable MFRM Wright map is unavailable for generalized fits. Use model-scale summaries for the named dimension instead. fit_report assembles the requested machine-oriented sections. Use fit_report(fit; view = :public) or fit_report_public for a reader-facing structured projection, and fit_report_markdown for a Markdown preview.

The top-level status describes model exposure (:supported or :experimental); it does not certify that every requested report section was computed. fit_report_health derives report-generation health from the section statuses. A captured status = :error section sets report_status = :incomplete, while :not_requested and :unsupported do not. Use require_complete = true on fit_report, report exporters, or fit_report_dossier when a failed requested section should stop export. Use on_section_error = :throw when the first failing section should abort immediately.

Report completeness and diagnostic quality are separate: a complete report can preserve MCMC warnings or unsupported sections. Read the diagnostic assessment and the status of each section needed for the claim. For positive loadings or consistencies, a posterior probability above zero reflects the imposed positive support and is not evidence of an effect. Define meaningful comparisons before interpreting these rows. In MGMFRM, consistency one is the model's product-one reference, not a calibrated reliability threshold.

Save the fit with save_fit_cache and reload it with load_fit_cache to regenerate tables and figures in the same environment without sampling again. Keep source data, analysis code, and environment/version information alongside portable reports; the serialized cache alone is not a durable analysis archive. Recorded-fit caches retain exact integrity hashes while allowing tiny roundoff differences in recomputed means and SDs. This neither changes the saved values nor establishes cross-version compatibility.

A report should state:

  • model family, threshold regime, dimensions, and constraints;
  • rating-design limitations;
  • priors and sampler controls;
  • convergence and predictive diagnostics;
  • the prediction target for model comparison;
  • unsupported features and the limits of generalization.

Experimental fixed-Q MGMFRM results must not be generalized to exploratory multidimensional models or freely estimated correlation structures.

For an ordinary scalar MFRM, the expected-score and information guide connects an explicit item/rater assessment design to conditional curves and saved report tables. Its information is distinct from posterior precision.
