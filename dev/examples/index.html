Examples

Unreleased documentation preview — 13 October 2026

This manual includes unreleased interfaces and examples. It is not the documentation of an installed release. Model support and scientific acceptance remain as stated on each page.

Install the matching development preview first. Repository-relative commands below assume that your working directory is the source checkout. After Pkg.add, locate a shipped example instead with include(joinpath(pkgdir(BayesianMGMFRM), "examples", "observed_icc.jl")) after using BayesianMGMFRM; substitute the desired example filename. An example that accepts your own cache/output paths still needs those arguments.

Ordinary binary IRT without raters

Question: how difficult are items I02 and I03 relative to I01? The ordinary Rasch/1PL example uses fixed artificial responses from 24 people to three items, with scores 0/1. It supplies no rater column and generates no new responses. Three items give limited information about each person's ability; this small example demonstrates the analysis steps, not a recommended test length or a parameter-recovery study.

using BayesianMGMFRM
include(joinpath(pkgdir(BayesianMGMFRM), "examples", "first_irt_analysis.jl"))
prepared = FirstIRTAnalysis.inputs()  # Inspect input and settings; no fit.
prepared.spec
analysis = FirstIRTAnalysis.main()    # Fit once and save.

The input operation is FacetData(responses; person=:person, item=:item, score=:score, rater=nothing, category_levels=0:1). The existing mfrm_spec and fit APIs then use P(correct) = logistic(ability - difficulty), with unit discrimination, no guessing parameter, and I01 fixed at difficulty zero. I01 is a reference convention, not an externally calibrated item. The prior is independent Normal(0, 1.5) for the 24 abilities and Normal(0, 1) for the two free difficulties. There are no free rater or step parameters. Changing the reference while simply reusing these independent priors can change the model. This is Bayesian joint estimation, not conditional maximum likelihood.

Four chains each use 1,000 warmup and 4,000 retained draws. The script saves a native fit.jls before calculating its answer.json. It reports 95% intervals and Monte Carlo errors for P001's ability and the two free difficulties. Positive difficulty means harder than I01; an interval crossing zero leaves that direction unresolved. The numerical check requires the whole-fit diagnostic gate (R-hat at most 1.01 and bulk/tail ESS at least 400, with sampler checks), mean MCSE at most 0.01 and each focal interval-endpoint MCSE at most 0.03 logit. These are example computational tolerances, not scientific effect thresholds. Keep warnings and unqualified results; successful computation alone does not establish model fit, prior suitability or interval calibration. The qualification shown by this example concerns its three focal quantities. In the local reference run they all pass, while eight other person intervals miss the same endpoint tolerance. Inspect posterior_mcse(fitted) for every parameter; passing focal checks does not qualify every ability interval.

Reopen a trusted saved fit in the same source/dependency environment:

cache = joinpath(analysis.directory, "fit.jls")
fitted = load_fit_cache(cache)
posterior_summary(fitted)
posterior_mcse(fitted)
review = FirstIRTAnalysis.main(["--saved-fit", cache])  # No refitting.

For your own data, preserve the explicit rater=nothing choice, use validate_design and mfrm_spec, select priors and sampler settings, then call fit(spec; ...). The ordinary score and information functions also apply to this unit-slope model. Existing reference tables use one fixed-zero no_rater level internally; it does not represent an observed judge. This entry does not provide free-discrimination, guessing or multidimensional IRT.

First MFRM analysis

Question: is R2 more severe than R1 after accounting for the people and tasks they rated? Follow this example before exploring the other model families. It uses 72 supplied artificial ratings from 12 people, four items and three raters, on categories 0–3. The ratings are fixed: running the example does not generate a new dataset. This is a teaching example, not a study of real raters. To run the same analysis one operation at a time, follow the connected API walkthrough. Choose that route or the complete script below; there is no need to fit both.

Run the analysis

After installing this checkout as described on the home page, run in Julia:

using BayesianMGMFRM
include(joinpath(pkgdir(BayesianMGMFRM), "examples", "first_analysis.jl"))
analysis = FirstMFRMAnalysis.main()

Including the file only defines the example's functions. The last line performs the fit and saves the result. From the source checkout, the equivalent command is julia --project=. examples/first_analysis.jl.

The example checks the data and fits a one-dimensional partial-credit MFRM. Each item has its own category steps. R1 defines zero rater severity, so rater[R2] is the R2−R1 contrast: positive means R2 is more severe, negative means R2 is less severe. Scores and logits are different units; a difference of 0.180 logit does not mean 0.180 score points.

R1's zero is a reference convention, not a claim that R1 is unbiased or an external calibration. See references and anchors before replacing it with a fixed calibration value.

Four Julia NUTS chains each use 1,000 warmup and 1,000 retained draws. The zero-centered normal prior scales are 1.5 for person coordinates and 1.0 for free rater, item and step coordinates. These are explicit settings for this artificial example, not universal defaults to copy into an applied study. The model explanation describes the probability model and constraints; prior implications explains what to examine when choosing a prior for your own data.

Read the answer

The reference calculation gives the following excerpt, rounded to three decimals:

Is R2 more severe than R1?
Artificial ratings: 72; people: 12; items: 4; raters: 3.
Positive values mean that R2 is more severe than R1, after accounting for persons and items.
Numerical checks: passed
Posterior mean: 0.18 logit; 90% interval: [-0.511, 0.889].

The estimate leans toward greater severity for R2, but the interval includes both negative and positive differences. These ratings do not clearly establish the direction of the difference under this model and prior. They also do not show that R1 and R2 are equivalent. A useful analysis can reach an uncertain answer; successful computation does not guarantee a clear empirical distinction.

The 90% central interval contains 90% of the computed posterior distribution. It describes uncertainty about the contrast conditional on the data and model. MCSE describes a different uncertainty: the numerical error from using finitely many posterior draws. In the reference result the mean MCSE is about 0.0069 logit and the two endpoint MCSEs are about 0.0171 and 0.0156. Small MCSE does not make the interval narrower or establish repeated-sampling coverage.

Before producing a substantive interpretation, the example requires the global diagnostic checks to pass, mean MCSE at most 0.01 and both endpoint MCSEs at most 0.02 logit. These numerical tolerances resolve this displayed example; they are not a minimum scientifically important difference. If checks fail, the answer says to withhold interpretation and preserves the fit for diagnosis. It does not silently rerun the fit or substitute a more favorable result.

The complete answer also prints the actual MCSEs and these illustrative limits, R-hat/ESS, and each chain's sampler diagnostics. It separates retained-draw divergences, maximum-depth hits, nonfinite log densities and E-BFMI from warmup events. Warmup records show recorded/expected iterations and whether history is available; unavailable counts are not zeros. Warmup events do not enter the retained-draw pass/fail rule. They remain visible even when that rule passes. Passing numerical checks does not establish model adequacy or interval calibration. answer.json preserves the full diagnostic summary and both sets of sampler rows, alongside the exact MCSE values, limits and their illustrative purpose.

Save and reopen without refitting

The returned analysis.directory is a new folder under results/first_analysis/:

FileUse
answer.txtRead the question, estimates, interpretation, MCSE limits and separate retained/warmup diagnostics.
answer.jsonReuse the computed answer, prior settings, numerical criteria and complete diagnostic summary/sampler rows in other software.
fit.jlsRecompute summaries or make figures from the saved posterior in the original environment.

The script reloads the fit and compares its answer with the original before finishing. In the same Julia session, inspect it yourself:

read(joinpath(analysis.directory, "answer.txt"), String)
restored = load_fit_cache(joinpath(analysis.directory, "fit.jls"))
FirstMFRMAnalysis.result(restored)

To regenerate the answer from that cache, without new MCMC, call:

reopened = FirstMFRMAnalysis.main([
    "--saved-fit", joinpath(analysis.directory, "fit.jls")])

This writes a new output folder and rejects a cache from different ratings, model or prior. In a later session, retain the original analysis project and Julia/dependency environment and supply the saved path; see reopening saved results. JSON and text can be read without restoring a Julia fit. For optional figures, use the plotting instructions with restored; figures need no refitting.

The example saves fit.jls and prints its absolute path before computing the answer. If summarizing or writing the answer fails after that message, keep the cache and the error details. After resolving the reporting problem in the matching environment, use `FirstMFRMAnalysis.main(["–saved-fit", "the printed path"]) to write the answer into a new folder without sampling again. A fitting or cache-writing failure before that message has no such saved-fit guarantee. This checkpoint preserves completed draws; it does not resume an interrupted sampler.

Move to your own question

First decide which contrast matters and what its units mean. Then check your rating allocation, category use, model assumptions and prior implications. Use the analysis workflow for that sequence. Moving to GMFRM, several dimensions or dependent ratings changes the model; it is not a required extra step in this one-dimensional example.

Observed-score ICC without fitting

The candidate's examples/observed_icc.jl compares four questions on the same three performances and two raters. Rater 2 always gives one point more.

include("examples/observed_icc.jl")
result = observed_icc_example()
[(r.definition, r.unit, r.icc) for r in result.results]
# (:agreement, :single,  2/3)
# (:agreement, :average, 0.8)
# (:consistency, :single,  1.0)
# (:consistency, :average, 1.0)

The perfect consistency coefficient reflects the identical ordering and spacing once the additive rater offset is removed. It does not mean the raw scores agree. The average coefficient concerns the mean of these two ratings. The example explicitly assumes equal score gaps and treats the raters as a fixed panel. See Choosing an ICC for the design, scale and uncertainty limits. This example performs no model fitting.

Observed-score alpha without fitting

The candidate's examples/observed_alpha.jl contains a complete small example:

include("examples/observed_alpha.jl")
result = observed_alpha_example()
result.ordinal.alpha
result.ordinal.observed_disagreement
result.ordinal.expected_disagreement
result.ordinal.singleton_observation_ids

The two coefficients use the same ratings but different declared measurement levels. Choose a level from the meaning of the categories, not whichever value is larger. See Observed-score alpha for the definition, exclusions and report integration.

The repository keeps runnable examples compact. These scripts are learning and verification examples rather than substantive analyses; they exercise the public surfaces described in the Bayesian Fitting page.

Inspect Data Without Fitting

Start with examples/inspect_ratings.jl to learn the input and model workflow without running MCMC or creating files. From a repository checkout with its dependencies installed:

julia --project=. examples/inspect_ratings.jl

The script constructs eight artificial ratings from two persons, two items and two raters on categories 0–2. It prints those counts, the complete category order, validation errors or warnings, and the equation for a one-dimensional partial-credit MFRM. A passing design check permits the next specification step; it does not make this tiny dataset adequate for inference.

In an interactive session, ?FacetData shows a complete input example, ?validate_design explains how to read its report, and ?mfrm_spec explains the model choice. ?fit gives a short fitting introduction; ??fit includes the full controls. The Julia help walkthrough explains the prompts and how these examples differ from R's example().

Minimal MFRM Workflow

examples/minimal.jl runs a short partial-credit MFRM sampler demonstration. For the complete first teaching analysis and its interpreted result, use First MFRM analysis. From the repository root, after installing the project's dependencies:

julia --project=. examples/minimal.jl

The script validates the ratings, constructs a specification and calls fit(spec; backend = :advancedhmc) for Julia NUTS. It prints the diagnostic flag, maximum R-hat, minimum bulk/tail ESS and posterior medians with 95% central credible intervals. It then saves the fit, reloads it and checks that posterior summaries are identical. Design inspection and manual cache keys are not required.

The two chains each use only 50 warmup and 50 retained draws. This is a short workflow demonstration, not a substantive analysis. Inspect any reported warnings with diagnostics(fit_result) when working interactively. A completed script or successful save/reload does not establish convergence or model validity.

For figures, install CairoMakie in the active Julia environment (for example, using Pkg; Pkg.add("CairoMakie")), then run:

julia --project=. examples/minimal.jl --plots

This mode loads CairoMakie before fitting and generates all figures from the reloaded fit. The default command does not load a plotting backend. Every run prints a new output directory under results/minimal/, retained after Julia exits. It contains:

FileContents
fit.jlsThe fit, retained draws, model/data information and diagnostics
rater-posterior.pdfRater medians and credible intervals, including the fixed reference
rater-chains.pdfRetained traces and rank histograms with diagnostic notes
category-predictive.pdfObserved versus replicated category proportions, using seed 42
wright-map.pdf, wright-map.svgStable MFRM facet measures and category boundaries on a shared scale

With the default Julia backend, only fit.jls is written without --plots. In a later session, use the printed cache path to regenerate and edit a figure without running the script or MCMC again:

using BayesianMGMFRM, CairoMakie
restored = load_fit_cache("results/minimal/<printed-directory>/fit.jls")
figure = BayesianMGMFRM.plot_posterior(restored; block = :rater)
content(figure[1, 1]).xlabel = "Rater severity (logits)"
save("rater-posterior-edited.svg", figure)

Replace <printed-directory> with the actual directory name. The plotting guide explains selection and intervals; the reports guide covers the separate report, table and bundle APIs. To export selected figures with the same report, use the figure bundle workflow.

With CmdStan configured, add --cmdstan (it can be combined with --plots):

julia --project=. examples/minimal.jl --cmdstan --plots

The same specification and workflow use backend = :cmdstan. Each CmdStan run gets a new cmdstan-build/ directory alongside its saved fit; compiled-model reuse is not attempted. See backend setup for runtime discovery and build requirements. Shared seeds do not imply identical draws across backends.

Synthetic paired-criterion ratings

examples/synthetic_paired_ratings.jl generates one pronunciation example with artificial persons, words, raters and responses. Run it from the repository root:

julia --project=. examples/synthetic_paired_ratings.jl

The example has 12 persons, 37 words, 19 raters and two criteria: ease of understanding and weak accent. Both scores range from 0 to 8, with higher scores indicating more of the named property. The design includes repeated ratings of the same recording, unequal word coverage, two sparsely covered words and a small amount of missingness in the first criterion. No empirical file is read. These counts and generating constants illustrate a design, rather than a recommended sample size or estimates from real speakers.

The printed output directory contains ratings.json (observed long-form ratings), recordings.json (all possible person–word cells and their assignment), truth.json (generating effects, correlations, complete assigned ratings and category probabilities), and manifest.json (seeds, equation, counts and file checksums). Missing first-criterion scores leave the second criterion intact; absent recordings are not assigned score zero. An optional argument selects a new output directory; existing directories are not overwritten.

Person correlation is 0.6 and residual recording correlation is 0.25. Recording effects are shared across raters, rater severity varies by criterion, and steps are shared across words within each criterion. These are generating conditions, not fitting priors. The realized correlation among 12 persons will differ from the population correlation. The script draws no posterior samples: the current MGMFRM fitting interface does not represent this complete recording/criterion structure. Use the example to inspect known truth and data handling; it does not establish parameter recovery or conclusions about real speakers.

Fixed-coefficient multidimensional MFRM

examples/multidimensional_mfrm.jl fits two named dimensions through BayesianMGMFRM.Experimental.fit and saves the fit and a report. Use either backend, optionally adding figures with CairoMakie:

julia --project=. examples/multidimensional_mfrm.jl
julia --project=. examples/multidimensional_mfrm.jl --cmdstan --plots
julia --project=. examples/multidimensional_mfrm.jl --correlated --plots
julia --project=. examples/multidimensional_mfrm.jl --correlated --prior-only --plots
julia --project=. examples/multidimensional_mfrm.jl --exchangeable --correlated --plots

Its fixed Q assigns items 1–2 to reasoning and items 3–4 to communication. Active coefficients and rater consistency are one; person/item locations use zero-centered priors, rater severities sum to zero, and latent correlation is identity. MFRMPrior sets standard deviations on free unit-logit coordinates. The experimental guide explains the model and limits. Add --correlated to estimate population rho with an LKJ(2) prior on either backend; its figures show rho and its chains. Ability-pair marginal standard deviations remain fixed prior inputs. Add --exchangeable to use an exchangeable zero-sum rater prior with kernel SD 0.4 for either model/backend. This selects Experimental.ExchangeablePrior for both the prior check and the fit; the default remains MFRMPrior.

Before fitting, the script prints prior parameter and rating summaries. Add --prior-only to stop there. --plots also saves ability-prior and rating-prior figures, plus a correlation-prior figure when --correlated is selected.

Each fitting run prints a new directory under results/multidimensional_mfrm/ containing fit.jls and report/. The script reloads the fit, checks its metadata and summaries, and reopens the report bundle, including prior parameter and rating summaries regenerated from the saved model. --plots adds prior figures and reasoning posterior and chain figures plus category predictive figures in PDF/SVG and their JSON inputs. Posterior figures use the reloaded fit; users need not reshape MCMC draws. The posterior intervals are central 90% intervals in unit logits. Fixed coefficients and derived coordinates are labelled; whole-fit diagnostic warnings remain visible. Report-only mode and subsequent bundle verification need no renderer.

The 50 warmup and 50 retained draws per chain are solely a workflow demonstration. A completed report does not establish convergence or scientific validity. To select another dimension later, load fit.jls and follow the saved-fit report example. Automatic request caching is unavailable for this model; manual save/reload is supported.

Guarded Scalar GMFRM Workflow

examples/guarded_gmfrm.jl fits the experimental scalar GMFRM through BayesianMGMFRM.Experimental.fit(spec):

julia --project=. examples/guarded_gmfrm.jl

Its discrimination = :rater configuration estimates positive item discrimination and rater consistency, with rater-specific partial-credit steps. The script validates the ratings, prints model-scale posterior summaries and MCMC diagnostics, then saves and reloads the fit. It does not fit additional task effects, multidimensional ability, rating-scale generalized kernels or DFF terms. See the experimental model guide for the response equation, identification and raw-coordinate prior.

Guarded Fixed-Q MGMFRM Workflow

examples/guarded_mgmfrm.jl uses the same experimental entrypoint for two named ability dimensions:

julia --project=. examples/guarded_mgmfrm.jl

Q rows follow data.item_levels; its columns follow the declared dimension labels. The script prints both orders and the matrix before fitting:

Itemreasoningcommunication
I110
I201

This is a confirmatory between-item example. Active positive item-by-dimension loadings and rater consistency are estimated even though the compatibility selector is discrimination = :none. Latent correlation is fixed to identity; item-specific partial-credit steps are used. The two-item toy dataset illustrates the API and is insufficient for substantive multidimensional conclusions. Exploratory loadings, free latent correlations, validated bifactor support and model-weight claims are outside this fitting route. The experimental model guide explains these restrictions.

Explicit normalized-prior MGMFRM workflow

Start with the bundled MGMFRM data

Question: what does a person's rating profile tell us about two separate abilities? The bundled examples/normalized_mgmfrm_ratings.jl contains 1,000 fixed artificial ratings from 50 people, five items and five raters. Categories are ordered 1–4. Two items measure the first dimension and three measure the second. Each item has an estimated positive loading on its assigned dimension; the other loading is fixed at zero. The dimension names dim=1 and dim=2 are deliberately generic because these are simulated teaching data, not a test with validated substantive constructs.

First inspect the inputs without estimating a model or creating output files. This is the default when no mode is supplied:

julia --project=. examples/normalized_mgmfrm.jl

Use --help to list the modes; --inspect-example explicitly selects the same inspection. Both inspection and help finish without sampling or writing results.

ModeWhat happens
No arguments or --inspect-exampleRead the fixed data and explain Q, dimension support, priors and proposed fit settings.
--help or -hPrint the available commands.
--fit-exampleRun the four-chain teaching fit and save/report its results.
--saved-fit PATHRead a trusted fit in its original environment and write a new report without fitting.
--demoRun a tiny demonstration with random draws and chains too short for inference.

--figures can accompany --fit-example, --saved-fit or --demo when CairoMakie is installed. It cannot accompany help or input inspection.

This prints the category order, item-to-dimension assignment, all six explicit prior scales and the proposed sampling settings. The table is incomplete: 250 of the 1,250 person/item/rater combinations are unobserved. They must stay absent; do not fill them with zero or a category value. This example retains all known persons, items and raters. It does not establish performance for arbitrary sparse or disconnected designs.

The model uses item-specific partial-credit steps, centered rater severities and positive rater consistencies whose product is one. Person dimensions have independent unit-SD priors; their population correlation is fixed at zero. The explicit normalized prior defines the scale of the remaining effects. Its supplied values reproduce this example, not a default choice for a new study; inspect the scientific scope before interpreting numerical qualification as calibration.

To estimate this fixed example, use the explicit fitting command:

julia --project=. examples/normalized_mgmfrm.jl --fit-example

It runs four Julia NUTS chains, each with 1,000 warmup and 1,000 retained draws, using seed 20261008110001, then writes the answer and saved results described below. It does not generate a new dataset or predictive replications. These inputs, prior and controls match an existing completed four-chain analysis; changing the data, prior, environment or controls requires checking the new diagnostics and MCSE. A fixed iteration count is not an accuracy guarantee.

In Julia, inspect or adapt the complete specification before fitting:

using BayesianMGMFRM
include(joinpath(pkgdir(BayesianMGMFRM), "examples", "normalized_mgmfrm.jl"))
prepared = NormalizedMGMFRMExample.example_inputs()  # no fitting
prepared.spec.q_matrix
prepared.prior
prepared.controls
# Execute only when you intend to run MCMC:
# fitted = BayesianMGMFRM.Experimental.fit(prepared.spec;
#     prior=prepared.prior, prepared.controls...)

Inspection also reports how many people have structural support for every ability direction and names those with missing dimensions. With your own data, start with CSV import and your own specification. example_inputs() always reads the bundled data. Build Q by item label and inspect person-level support before fitting; the worked incomplete-assignment check shows why overall data validation can pass while one ability remains unmeasured.

The fixed ratings are shipped with the source; the previous posterior is not. Use your printed fit.jls path with --saved-fit for later reporting. The explicit --demo command below uses different, tiny data and deliberately short chains; it is not this teaching analysis.

If the program prints Saved fit before reporting: and a later export fails, keep that cache and fix the reported problem. In the original environment, use --saved-fit "the printed path/fit.jls" to create a new output folder. Do not rerun --fit-example to recover a report. Preserve the failed output folder until the new bundle has been verified; a partly written report is not a verified bundle. See export recovery.

Read an existing MGMFRM analysis

Question: what abilities does the fitted model estimate in each dimension? Use your trusted normalized MGMFRM cache in the original Julia/dependency environment. This route reads the original model, data, prior and all retained chains; it performs no new fitting, prior simulation or predictive random draws.

using BayesianMGMFRM
include(joinpath(pkgdir(BayesianMGMFRM), "examples", "normalized_mgmfrm.jl"))
analysis = NormalizedMGMFRMExample.main(["--saved-fit", "path/to/fit.jls"])
read(joinpath(analysis.directory, "answer.txt"), String)

From a source checkout, the equivalent command is julia --project=. examples/normalized_mgmfrm.jl --saved-fit path/to/fit.jls. The cache must be a NormalizedMGMFRMFit produced by the documented fit/save route; it is not a raw research sample file or a portable JSON report. See saved-result reproduction for selecting the matching environment.

The answer prints the observed sample sizes, retained draws, whole-fit numerical status and the first person's estimate and 95% central interval in each named dimension. The two values describe different abilities; they are not an overall ranking or evidence that one trait is intrinsically higher. Their scale comes from the saved model and prior. This model fixes latent correlations at zero; correlating the printed person estimates is not estimation of that population correlation.

The new output folder contains answer.txt, a verified fit.jls copy and report/ with readable Markdown, portable JSON and parameter tables. The report includes all people, the actual prior, and mean/interval-endpoint MCSE. A narrow interval and small MCSE answer different questions. Numerical warnings remain visible and the answer says to withhold interpretation when the whole-fit diagnostics fail. Passing diagnostics still requires judging numerical precision against the reported quantity and does not establish calibration or model adequacy. No WAIC/LOO comparison or new observation IDs are invented for the saved analysis.

The saved route has also been exercised on a completed four-chain MGMFRM with 1,000 retained draws per chain, using an existing simulated validation dataset: 1,000 training ratings from 50 people, five items and five raters. The incomplete allocation retains known facet levels. That validation cache is not bundled with the package; supply your own trusted fit in the command above. This checks the existing-sample reporting route; it is not a new fit or evidence for extreme sparsity. The scientific scope, including prior sensitivity and undercoverage, still applies.

Short interface demonstration

The bundled source file examples/normalized_mgmfrm.jl is a self-contained two-dimensional, fixed-Q example with estimated positive loadings and identity latent correlation. The following commands run a short interface demonstration, including prior/predictive random generation; they do not produce an analysis suitable for substantive interpretation:

julia --project=. examples/normalized_mgmfrm.jl --demo
# With CairoMakie installed in the analysis environment:
julia --project=. examples/normalized_mgmfrm.jl --demo --figures

It specifies all six normalized exchangeable-prior scales, inspects prior rating implications, and fits with the explicit location coordinates. Two chains with 10 warmup and 12 retained draws demonstrate the interface; their warnings remain visible and these settings are insufficient for inference. The script prints model-scale summaries and Monte Carlo errors, saves to a new directory under results/normalized_mgmfrm/, and checks metadata, summaries and diagnostics after reloading fit.jls.

The optional person and loading-diagnostic figures use the reloaded fit and the first named dimension and are saved under figures/. The --figures option can also accompany --saved-fit; it requires CairoMakie in that analysis environment. The report reader verifies the exported bundle; report completeness does not mean MCMC diagnostics passed. This workflow uses AdvancedHMC. See the explicit prior contract for the separate raw-coordinate CmdStan route and the meaning of the illustrative scales.

Correlated MGMFRM Workflow

examples/correlated_mgmfrm.jl constructs a two-dimensional pure-Q panel, explicitly chooses GeneralizedPrior, simulates prior rating implications, fits the population correlation with estimated loadings/consistency, and prints diagnostics, rho precision and a conditional posterior-predictive comparison. It verifies the same MCSE, category probabilities and seeded score replications after save/reload, then saves and reopens a reader-facing report with tables.

julia --project=. examples/correlated_mgmfrm.jl

Add --cmdstan to use the matching backend. The example uses only 10 warmup and 12 retained iterations in each of two chains; the resulting warnings must not be interpreted as inferential acceptance. Each run prints a new directory under results/correlated_mgmfrm/ containing fit.jls and a report/ bundle. Add --figures in an environment containing CairoMakie to include loading, rho-diagnostic, prior and predictive PDF/SVG figures with their numerical inputs. Each difference is calculated within the original joint draw, including the reference rater's fixed zero. Scalar MFRM differences use unit logits; do not apply the MGMFRM multiplier of 1.7. Positive severity means the left rater is more severe under this model, not less fair. A reference or hard-anchored rater can be one side of the comparison; two fixed coordinates are rejected because neither is estimated. External anchor uncertainty is excluded.

Keep the native fit, the saved answers and their environment together. Inspect the whole-fit warning, contrast diagnostics and interval-endpoint MCSE before interpreting a result; a probability above zero is not an automatic practical decision. This scalar method provides differences, not consistency ratios, cross-model contrasts or fixed-Q multidimensional MFRM contrasts.

Compare abilities or raters in a saved MGMFRM fit

Use a joint posterior contrast to ask whether two fitted persons differ within one dimension, or whether two raters differ in severity or consistency. Subtract the two values at each retained draw: subtracting marginal interval endpoints or independently shuffling the columns loses their posterior dependence. For example, the variance of a difference includes minus twice the covariance, even when the population ability prior has identity correlation.

The qualified BayesianMGMFRM.posterior_contrast function accepts independent fixed-Q MGMFRMFit and Experimental.NormalizedMGMFRMFit caches. It uses the fitted model coordinates with all original chains and draws; no renderer or additional diagnostic dependency is needed:

Load only trusted serialization files. This retains the computed answer and its source/coordinate metadata; it does not archive the fit or provide portable posterior draws. Reopen the native fit in its recorded environment to calculate a different contrast. Existing caches are not changed by this operation.

Positive contrasts mean that the left person has higher ability, the left rater is more severe, or the left rater has larger consistency. The consistency contrast is log(left) - log(right): zero means equal multipliers. Its ratio_interval exponentiates the log-scale median and interval endpoints; this is not a posterior mean ratio, and its MCSE remains on the log scale. Unrepresentable ratio endpoints are marked unavailable.

Ability-difference magnitudes use the saved model's ability unit. A common origin shift cancels, but positive rescaling multiplies the difference and any nonzero ROPE bounds; the sign is invariant. Item-location differences require additional care when loadings differ: even their sign can depend on the ability origin. See Estimands, origins and units before interpreting contrasts across models or prior settings. Invariance of a contrast does not make its posterior independent of the chosen prior.

summary contains a central 90% credible interval by default, mean/SD and quantile MCSE, and rank-normalized split R-hat plus bulk/tail ESS for the contrast itself. Inspect those diagnostics as well as whole_fit_diagnostics; one contrast cannot clear warnings elsewhere. Short or constant sequences keep unavailable diagnostics and precision. No new acceptance threshold is applied.

An optional two-bound rope specifies a practically negligible range on the contrast's scale. The illustrative consistency bounds above correspond to ratios from 0.8 to 1.25; they are not a recommended tolerance. Justify bounds before inspecting the posterior, or omit them. Event rows report the posterior fraction above zero and, if requested, below/inside/above the ROPE, with MCSE computed from the ordered indicator draws. All-zero or all-one indicators retain unavailable MCSE: an observed fraction of zero or one is not proof of exact posterior certainty. No equivalence decision, multiplicity adjustment, or rater reliability classification is made. A contrast still depends on the fitted model, prior and rating design; it does not establish agreement on future scores.

Check a mean-profile contrast in the intended units

After fitting, ask whether rater B is more severe than A. A positive B−A difference means B assigns lower scores at otherwise equal conditions. Load your saved profile-fit.jls in its original Julia/dependency environment. The following recipe only reads retained draws; it does not fit again.

The units=:unit_logit argument used when preparing the prior specifies the input means. It does not change the units returned by posterior_contrast. For this independent D1 model with both coefficients fixed at one, multiply the model-coordinate severity difference, interval and MCSE by the likelihood constant 1.7 to express them in unit logits. This conversion is not a general rule for free coefficients or the ordinary scalar MFRM, which already uses unit logits.

using BayesianMGMFRM
restored = load_fit_cache("profile-fit.jls")
restored isa BayesianMGMFRM.Experimental.NormalizedMGMFRMFit ||
    error("Use the normalized fixed-one mean-profile fit for this example.")
meta = fit_metadata(restored)
(meta.dimensions == 1 && meta.loading_policy === :fixed_one &&
    meta.rater_consistency === :fixed_one) ||
    error("This scale conversion requires the D1 fixed-one model.")
contrast = BayesianMGMFRM.posterior_contrast(restored;
    left="rater[B]", right="rater[A]", interval=0.95)
s = contrast.summary
p = s.precision
d = s.contrast_diagnostics
scale = meta.likelihood_scale
unit_logit = (; mean=scale*s.mean, lower=scale*s.lower, upper=scale*s.upper,
    mean_mcse=scale*p.mean_mcse,
    endpoint_mcse=(scale*first(p.quantiles).mcse, scale*last(p.quantiles).mcse))

# Illustrative limits, chosen before fitting; specify suitable limits for your study.
limits = (; mean_mcse=0.01, endpoint_mcse=0.02) # both in unit logits
valid = x -> x isa Real && !(x isa Bool) && isfinite(x) && x >= 0
checks = (;
    whole_fit=contrast.whole_fit_diagnostics.passed,
    contrast_diagnostics=d.status === :available &&
        all(valid, (d.rank_normalized_rhat, d.bulk_ess, d.tail_ess)) &&
        d.rank_normalized_rhat <= 1.01 && d.bulk_ess >= 400 && d.tail_ess >= 400,
    mean_mcse=p.mcse_status === :available && valid(unit_logit.mean_mcse) &&
        unit_logit.mean_mcse <= limits.mean_mcse,
    endpoint_mcse=p.mcse_status === :available && all(valid, unit_logit.endpoint_mcse) &&
        all(x -> x <= limits.endpoint_mcse, unit_logit.endpoint_mcse))
result = (; unit_logit, limits, checks, numerically_qualified=all(values(checks)),
    warmup=diagnostics(restored).warmup_rows)
result

Different recorded environments and controls need their own results; these numbers are an illustration, not an exact-output promise for every new run.
