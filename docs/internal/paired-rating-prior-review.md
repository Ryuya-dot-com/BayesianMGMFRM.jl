# A0の事前の含意：尺度・ステップ形状と次の精度確認

更新：2026-09-21。対象は[合成応用例のA0](paired-rating-reference.md)です。今回の比較から、端点への集中には語・評価者・録音の分散だけでなく、ステップの並び方が強く関わると分かりました。ただし、どの事前を採用するか、昇順制約が応用上必要かは未決定です。既存の推定式・事前・保存標本は変更していません。

## 1. 問いと比較の役割

前の共同事前予測では、0–8点の両端への頻度が平均約61–62%となり、合成観測値の約23–32%より高くなりました。今回の問いは「なぜそのような反応分布を生むのか」です。次の三点を区別します。

1. 語・評価者・録音の差が広すぎるために、潜在的な評定位置が両端へ押し出されるのか。
2. ステップの広がりを変えるだけで、中間カテゴリーを使う確率や領域は変わるのか。
3. 同じステップ値でも、その並び順によって中間カテゴリーの役割が変わるのか。

事前予測は事前が許すデータの形を調べる手段です。観測頻度との近さによって事前を自動的に最適化する手続きにはしていません。この位置づけは[Stanの事前予測の説明](https://mc-stan.org/docs/stan-users-guide/posterior-predictive-checks.html)とも対応します。

比較は、前の結果を見て立てた**探索的な機構の検討**です。その上で、今回の7条件・256 draw・指標を[実行前の設計記録](../../results/workflows/20260921-paired-prior-review-01/design.json)に固定しました。既存の共同事前drawを全条件で共有し、条件を追加・選別せずに一度の比較を行っています。確認的研究の事前登録や独立レビューを実施済みという意味ではありません。

## 2. 反応式から分かること

一つの基準・評定行を考え、`eta = theta - word - rater + recording`、H=`K-1`、`S_k = sum(s_1,...,s_k)` とします。PCMのカテゴリー確率は

```text
p_k(eta) = exp(k*eta - S_k) / sum_{j=0}^H exp(j*eta - S_j),
S_0=0, S_H=0.
```

数値実装は最大値を引いたlog softmaxで計算します。上式は機構を説明する表記です。

### 2.1 端点の重みと中間カテゴリー

ゼロ和のステップでは、0点とH点の非正規化重みはそれぞれ `1` と `exp(H*eta)` です。ステップの並び替えではこの二つが変わらず、分母の中間カテゴリーの重みが変わります。

同じH個の値を昇順にすると、最初のk個の累積和は、任意の並び順の最初のk個の和以下です。したがって昇順では全ての中間カテゴリーの非正規化重みが元の並び以上となり、分母が増えます。**同じeta・同じステップ値の集合では、昇順への並び替えによって両端確率の合計が増えることはありません。** 降順は逆の側の限界を与えます。これは今回の乱数結果だけに依存する傾向ではなく、この反応式から導かれる性質です。

一方、全ステップ0は一般には「一様な評定」ではありません。eta=0のときだけ全カテゴリーが等確率です。etaが0から離れると重みは `1,exp(eta),...,exp(H*eta)` となり、片側の端が強くなります。

### 2.2 順序制約とスコアの意味

ステップが非単調でも、有限なパラメータでは全カテゴリー確率が正で、`d E[Y|eta] / d eta = Var(Y|eta) > 0` です。したがって、ステップが昇順でないこと自体は、PCMの計算が無効であることや、期待スコアの方向が逆になることを意味しません。

ただし、「ある中間カテゴリーが最も生じやすいetaの領域を持つか」は別の問いです。カテゴリーkが一意の最頻カテゴリーとなる開区間は、

```text
lower_k = max_{j<k} (S_k-S_j)/(k-j)
upper_k = min_{j>k} (S_j-S_k)/(j-k)
lower_k < eta < upper_k
```

で求められます。空の側はそれぞれ負／正の無限大です。`lower_k >= upper_k` なら幅のある領域を持ちません。有限のetaグリッドを走査する近似ではなく、この交点を直接計算しました。正の定数でステップ全体を拡大しても、上下限が同じ倍率で拡大するため、この領域を持つカテゴリーの**個数**は変わりません。狭い領域の位置や幅、実際の出現頻度は変わり得ます。

全ステップが厳密に昇順なら、全カテゴリーがそのような領域を持ちます。全0では中間カテゴリーはeta=0で同率になるだけで、幅のある領域は両端にしかありません。この指標は**観測されたカテゴリー数でも、十分に測定できるカテゴリー数でもありません**。領域があっても、想定する話者の範囲から離れていたり非常に狭かったりすれば、応用ではほとんど使われません。

### 2.3 評定位置の尺度

現在の事前で一つの評定行のetaの周辺分散は、

```text
Var(eta_c) = 1 + word_sd^2 + rater_sd_c^2*(1-1/R)
             + exp(2*recording_log_sd_mean_c + 2*recording_log_sd_sd_c^2).
```

話者の周辺SD1は、負荷量1と単位ロジットを固定したA0では母集団の広がりへの追加仮定です。単なる尺度の取り直しではありません。自由負荷量を同時に調整できるモデルの尺度識別とは区別します。[批判点検の導出](strategic-review-2026-09-21.md#r2高数式上確認a0の話者sd1は単なる尺度定義ではない)を参照してください。評価者の項はゼロ和射影による分散を使い、録音の項はLogNormal SDの二乗の期待値です。現在の19評価者では二基準で約2.649と3.081です。語・評価者・録音のSDを半分にすると約1.412と1.520になります。これは有限パネルの実測分散を強制的に標準化した値ではありません。

この比較で話者SDまで半分にはしていません。A0の固定SD仮定を保ちながら、残る三つの効果をまとめて縮めた場合の感度を調べています。三つのうちどれが個別に重要かまでは今回の比較では分離していません。

今回の[実装](../../scripts/paired_rating_prior_review.jl)は応答確率の比較に限り、昇順・全0条件には利用可能なfit priorがないことを機械可読の記録に明記しています。

## 4. 比較結果

同じ256個の共同事前drawに条件付けたカテゴリー確率を、各基準で等録音重み、録音内では等評価者重みで平均しました。実現したスコアの乱数変動は積分しています。従って、前回の反復スコア頻度とはわずかに数値が異なります。対応差のMCSEは各drawの差から計算し、二つの平均のMCSEを独立として合成しません。

| 条件 | 分かりやすさ：端点確率 | 基準との差（MCSE）、ポイント | 訛りの弱さ：端点確率 | 基準との差（MCSE）、ポイント |
| --- | --- | --- | --- | --- |
| 基準 | 61.98% | 0 | 61.06% | 0 |
| 付随効果SDを半分 | 54.40% | −7.58（0.16） | 52.54% | −8.52（0.18） |
| ステップSDを2倍 | 58.42% | −3.56（0.46） | 55.35% | −5.72（0.50） |
| SD半分＋ステップSD2倍 | 50.88% | −11.10（0.57） | 46.79% | −14.28（0.63） |
| 同じステップ値を昇順 | 40.54% | −21.44（0.64） | 38.82% | −22.24（0.71） |
| SD半分＋昇順 | 30.95% | −31.04（0.67） | 28.20% | −32.86（0.73） |
| 全ステップ0 | 62.89% | ＋0.91（0.54） | 63.92% | ＋2.86（0.61） |

全etaのどこかで一意の最頻カテゴリーとなる幅のある領域を持つカテゴリー数は、元の事前で平均**3.64／3.83個（9個中）**でした。ステップSDを2倍にしても個数は変わらず、昇順では9個、全0では2個です。

したがって、今回の設定では「全体の事前SDを調整すれば十分」とは言えません。並び方によって、多くの中間カテゴリーが最も生じやすい領域を持たないという含意も変わります。ただし、昇順を採用するかは、9段階それぞれに固有の評価領域があることを応用上仮定したいかに依存します。端点確率を下げること自体を改善の定義にしていません。今回の順位を使って最も観測値に近い条件を選ぶこともしません。

[比較図](../../results/workflows/20260921-paired-prior-review-01/prior-mechanisms.png)・[全カテゴリーの数値](../../results/workflows/20260921-paired-prior-review-01/current-review.json)・[検証記録](../../results/workflows/20260921-paired-prior-review-01/verification.json)を保存しています。Julia 1.12では1,945項目、1.10では1,932項目通過しました。件数の差は、小さい乱数テストで一意の最頻領域を持つカテゴリー数が版によって違うためです。本比較は両版とも**同じ保存済み256 draw**を読み、全条件のdraw別カテゴリー確率は最大差 `2.22e-16` でした。新たなMCMC、回復・被覆・SBC、事後の事前感度評価は実行していません。

## 5. 科学的な判断として残ること

判断すべき点は、9段階を単なる順序付き評定として扱うのか、それぞれが潜在位置のある範囲で最も選ばれやすい段階であることまで期待するのかです。前者では順序制約なしのPCMも候補であり、後者ではステップ形状に関する事前の説明が必要になります。

選択肢は、現在の交換可能なステップを保つ、昇順制約を別モデルとして定義する、または順序違反も許すが位置ごとに傾向を持つ事前を別途定義することです。今回の比較は最後の候補を評価していません。いずれも、尺度、事前の意味、応用の問いを先に明示してから採用します。合成生成器が昇順の固定ステップを使ったことを、実際の評定尺度が昇順である証拠にはしません。

位置・尺度については、話者の母集団平均0・SD1、評価者とステップの基準別ゼロ和を区別します。語難易度の平均と話者の有限標本平均はハードなゼロ和ではなく、properな母集団事前で支えます。同じ尤度を保つ位置の移動が事前によって区別される部分があるため、properな事後であることをデータだけによる強い識別と同一視しません。12話者からの話者相関、低被覆語、共通ステップと語難易度の依存は、事前選定後の精度・感度・回復評価でも確認します。

## 6. 次の費用パイロットで確認する量と判定案

以下は**計算上の精度を確認する提案**です。実用上の最小差、許容される誤分類、モデル採用基準ではありません。焦点量を保存標本から復元する実装と資源監視は、[後続の限定検証](paired-rating-precision.md)まで完了しました。科学的な事前選定と、コンパイル・総予算・監視権限を含む実行契約が整うまで、新しい推定の開始指示にはしません。

### 6.1 焦点量の固定

| 問い | 保存標本から作る量 | 選別を避ける指定 |
| --- | --- | --- |
| 話者プロフィールの差をどの精度で報告できるか | 基準ごとの `theta[p,c]-theta[p',c]` | 全話者対。12話者なら132対比。結果を見て最大差だけ選ばない |
| 評価者間の差はどの程度か | 基準ごとの `rater[r,c]-rater[r',c]` | 全評価者対。19人なら342対比。生の平均点差や共通の一貫性効果と混ぜない |
| 話者差と録音差の依存を区別できるか | `rho_person`、`rho_recording`、二つの録音SD | zを要約後に変換せず、各drawのモデル尺度で計算 |
| 指定した録音の評定分布を報告できるか | 既知／未知録音の全カテゴリー確率と非自明な累積確率 | ID順で最初の適格3録音／未観測の話者×語3組、全既知評価者・二基準。これは数値計算の焦点設計であり、代表的な予測性能の評価標本ではない |

通常の全パラメータ診断も併記します。焦点量を作る際にチェーン配置を保ち、相関・SD・対比を各共同drawから計算します。最後の累積確率1や、K=2で固定されるステップ0は構造的定数として区別します。単に全drawが同じになった未知パラメータを構造的定数とは扱いません。

### 6.2 診断と数値精度を混同しない

4チェーン、rank-normalized／folded split R-hatの最大値が1.01未満、bulk／tail ESSが各400以上、保持drawの発散0、有限な密度・焦点量、チェーン別E-BFMIを出発点とします。E-BFMI 0.3未満は要調査とします。これらは[Stanの診断指針](https://mc-stan.org/learn-stan/diagnostics-warnings.html)に沿った計算確認の条件であり、事後分布を十分探索したことの証明ではありません。

木深さ上限の到達は費用・効率の警告として件数と割合を残します。深度到達だけから推定の偏りを断定しません。現在の短い標本は全drawが深度上限で、さらに標本不足のため、精度を判断できる段階にはありません。

平均のMCSEはbulk ESSから単純に置き換えず、対象の平均に対する推定を使います。[Stanの事後解析](https://mc-stan.org/docs/reference-manual/analysis.html)が説明するように、依存した標本では生のdraw数と有効な標本数は異なります。95%区間の両端には、平均のMCSEとは別に2.5%・97.5%分位点のMCSEを計算します。[分位点MCSEの定義](https://mc-stan.org/posterior/reference/mcse_quantile.html)を参照してください。

| 量 | 数値精度の提案 | 意味・適用条件 |
| --- | --- | --- |
| 対比、相関、録音SDの事後平均 | `MCSE(mean) / posterior SD <= 0.05` | 事後のばらつきに対して数値誤差を小さくする。応用上小さい差を測れることとは別 |
| 上記の95%区間の両端 | 各端の `MCSE(quantile) / width(CI95) <= 0.05` | 区間端の数値的な不確実性も表示する。幅が0の非定数やMCSE未計算は通過としない |
| 予測確率の事後平均 | MCMC MCSEが0.01以下という出発案 | 1パーセントポイントは計算上の表示精度案。合否・校正の許容誤差ではない |
| 未知録音の追加積分 | MCMC誤差と分けて記録し、上の確率精度に十分小さいことを検証 | 現在の最終平均に対する内側MCSEだけでは、draw別確率や分位点の精度は保証しない |

予測確率については、[draw別の周辺確率の復元](paired-rating-precision.md#3-未知録音の積分とmcmc誤差)を実装しました。適応求積の誤差推定値を別に保存し、乱数による内側標本を加えずにMCMC MCSEを計算します。同じ積分誤差をMCSEへ再び加算しません。区間も表示するため、実装では予測確率にも上記と同じ区間端の精度条件を加えました。この追加条件も工学上の提案です。以前の集計された予測JSONだけから、純粋な事後MCMC誤差や区間端の誤差が分かったとはしません。

診断不良、MCSE未計算、精度不足、費用上限到達をそれぞれ別の状態で保存します。条件を満たす焦点量の割合だけで全体を受け入れず、不十分な量の一覧も残します。実用的な許容差は未設定なので、全数値条件を通過しても科学的・応用上の受入は別です。

### 6.3 費用と停止の順序

[既存の費用パイロット案](applied-mgmfrm-acceptance.md#6-計算量を先に膨らませない実行案)を維持します。独立したパイロット用合成データ1組に対してJulia／CmdStan各1推定、各4チェーン・500 warmup＋500 retained／chainまでです。1推定30分、全体60分（コンパイル込み）、プロセス群8 GiB、総出力2 GiBは上限候補であり、実測予想時間ではありません。

実行前にデータ・事前・コード・制御・焦点設計と計測方法を保存します。資源上限は実行中に監視し、超過したら子プロセスを含めて停止します。500＋500まで実行できた場合に診断・MCSEを判定し、途中で都合のよい推定値になったことを理由に停止しません。未達でも自動延長・再試行を行いません。残るバックエンドの実行は、最初に指定した全体予算内であることを確認します。

今回の事前比較の実行時間はこのサンプラー費用の予測には使えません。ログの累積allocationも、同時に使ったメモリのピークとは違います。実行中のプロセス群メモリ・出力上限の監視と焦点量consumerは、[限定した検証](paired-rating-precision.md)を通過しました。ただし監視はポーリングであり、厳密な容量の割当制限ではありません。通常サンドボックスでの観測不能は起動前に停止します。科学的な事前選定と、監視を実行できる権限を含むパイロット契約が未確定なので、実行準備全体が完了したとは扱いません。

## 7. 更新した順序

1. 今回明らかになった「中間カテゴリーにどの役割を期待するか」と尺度・識別を、応用の問いとともに判断する。作成者による数式点検と独立レビューを区別する。
2. 採用候補が現行事前族なら明示値を固定する。新しいステップ事前が必要なら別の正規化ターゲットとして両バックエンドを実装し、事前予測まで確認する。
3. 検証済みの焦点量consumerと費用上限監視を使い、コンパイル・出力先・共有時間と出力予算・監視権限を含む契約を固定してから、限定した費用パイロットを実行する。今回のconsumer検証では新たな推定を行っていない。
4. 得られた費用と精度から、回復・被覆・事前感度・録音単位の予測評価に必要なロスターと反復数を定める。元の短い標本や今回の256事前drawを、その評価の成功反復へ算入しない。

パッケージ全体では、通常APIへの統合、一般化モデルの科学的受入、独立した再現と初見利用者の確認が引き続き残ります。この応用の事前選定を、全てのMGMFRMの既定値を変更する根拠にはしません。
