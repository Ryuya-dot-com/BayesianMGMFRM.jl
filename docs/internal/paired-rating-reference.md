# 合成応用例の A0 参照推定

更新：2026-09-21。これは応用モデルの限定的な参照実装です。通常の `MGMFRMFit` や公開APIに録音効果が追加されたことを意味しません。科学的な受入・反復回復・SBC・十分な事後精度の判定は別に残ります。

[応用の問いと検証設計](applied-mgmfrm-acceptance.md)で定義した、二基準の話者プロフィールと、話者差／録音差／評価者差を区別するための A0 を実装します。[Julia](../../scripts/paired_rating_reference.jl)と[Stan](../../scripts/stan/paired_rating_reference.stan)は同じ自由座標と正規化された密度を使います。MGMFRM の `1.7`、自由負荷量、評価者一貫性の推定は含めません。

## 問いと反応式

高いスコアを「分かりやすい／訛りが弱い」とした `Z=0,...,K-1` に対し、

```text
log Pr(Z_pwr,c=h) / Pr(Z_pwr,c=h-1)
    = theta_p,c - b_w,c - r_r,c + u_omega,c - s_c,h
omega = (p,w), c in {1,2}, h in {1,...,K-1}
```

同じ録音の全評価者に `u_omega` を共有し、同じ基準内で全語にステップを共有します。話者相関と録音相関は異なるパラメータです。評価者は基準別ゼロ和、非基準カテゴリーのステップも基準別ゼロ和とし、保存上の `s_c,0=0` は別に固定します。ステップの順序制約は課しません。合成真値のステップが単調であることは、推定の事前制約ではありません。

入力は観測済みの縦長評定だけです。全二基準は必要ですが、個々の評定の片方欠測、未出現カテゴリー、不均衡な語被覆は許容します。出現しないカテゴリーを理由にデータを引き直しません。同一録音・評価者・基準の重複、録音IDと話者×語の不整合、範囲外スコアは拒否します。現在は1話者×語に1録音、2基準、2–20カテゴリー、2評価者以上の参照実装です。複数の試行・録音を同じ話者×語に持つモデルはこの契約に追加していません。

録音パラメータは**観測された録音だけ**に持ちます。不在の産出へのスコア補完はせず、未知録音の予測には後述の積分が別途必要です。弱い被覆や一基準しか観測されない水準について、proper な事前分布で推定可能であることを、データに十分な情報があることと同一視しません。

## 必須の事前入力と尺度

事前分布に既定値はありません。`Target(...; prior=...)` で全フィールドを明示します。

| 対象 | 分布・意味 | 入力 |
| --- | --- | --- |
| 話者の二次元効果 | 平均0、周辺SD1、相関 `rho_person` の二変量正規。有限標本を再中心化・再標準化しない | 固定負荷量1・単位ロジットに対する母集団SDの固定仮定。単なる単位の選択ではない |
| 語×基準難易度 | 独立な `Normal(0, word_sd)` | `word_sd > 0` |
| 基準別の評価者 | ゼロ和部分空間上で交換可能。全ベクトルの共分散は `rater_sd[c]^2 (I-11'/R)` | `rater_sd` の二つの正値 |
| 基準別の共通ステップ | H=`K-1` のゼロ和ベクトル。共分散は `step_sd[c]^2 (I-11'/H)`。K=2では全ステップ0 | `step_sd` の二つの正値 |
| 録音効果 | 平均0、SD `sigma_1,sigma_2`、相関 `rho_recording` の二変量正規 | SDと相関を推定 |
| 録音SD | `log(sigma_c) ~ Normal(mu_c, v_c)`、したがってSDはLogNormal | `recording_log_sd_mean`、`recording_log_sd_sd > 0`。後者は分散でなく標準偏差 |
| 二つの相関 | 独立な2次元LKJ。`p(rho)= (1-rho^2)^(eta-1) / B(1/2,eta)` | `person_lkj_eta`、`recording_lkj_eta`。既存の数値ヘルパーに合わせ整数1–10,000 |

今回の工学的な試運転では、語SD1、評価者SD `(0.5,0.6)`、ステップSD `(0.7,0.8)`、録音log-SDの平均 `(log(0.5),log(0.6))`・SD `(0.5,0.6)`、LKJ形状は話者2・録音5を明示しています。二基準で異なる尺度と二つの異なるLKJ形状も通ることを確かめる設定です。合成真値から推定した事前や、科学的に選定済みの推奨値ではありません。応用上の結果を解釈する前に、事前予測と感度検討が必要です。

## 自由座標と正規化

サンプラーの座標は、話者・録音の標準正規変数、語難易度、最終要素以外の評価者とステップ、二つのlog-SD、二つのFisher zです。

```text
rho = tanh(z), delta = exp(log(1-tanh(z)^2)/2)
theta_1 = z_person,1
theta_2 = rho_person * z_person,1 + delta_person * z_person,2
u_1 = sigma_1 * z_recording,1
u_2 = sigma_2 * (rho_recording * z_recording,1 + delta_recording * z_recording,2)
```

`log(1-tanh(z)^2)` は既存の安定な式で計算し、tanh が浮動小数点上で±1に丸められた後の差から計算しません。この非中心化により、録音SDが小さい領域でもサンプラーの標準正規変数とSDの強い幾何学的依存を避けることを狙います。良好な混合を保証するものではありません。

話者・録音の白色化変数には標準正規密度を直接置きます。モデル座標の二変量正規密度を評価する方法では、変換の行列式を加えると同じ密度になります。両方を重ねて加えません。各相関は `rho=tanh(z)` のヤコビアンを含むため、z座標の密度は `-log B(1/2,eta) + eta*log(1-rho^2)` です。録音のlog-SDには正規密度を直接置くため、さらにlog-SDヤコビアンを加えません。LogNormal密度に `d sigma/d log(sigma)` を加えた場合と一致します。

n要素のゼロ和ベクトル `v` は、最初のn−1要素を自由に持ち、最後を負の和で再構成します。その自由座標に対する正規化密度は

```text
log p(v_free) = 0.5 log(n) - (n-1) log(tau)
               - 0.5 (n-1) log(2 pi) - sum(v^2)/(2 tau^2).
```

これを評価者とステップへ基準別に適用します。「自由要素へ独立な正規分布を置くだけ」という別の事前には置き換えません。

Juliaの勾配は、カテゴリーの期待スコアと累積確率から解析的に計算し、非中心化とゼロ和の連鎖律を適用します。全736自由パラメータについて、各評定を何度も走査する数値微分をサンプリングの既定経路にしません。独立した密度式、ForwardDiff、方向差分、Stan自動微分で正しさを確認します。

## 推定・保存・読取り

リポジトリルートで `include("scripts/paired_rating_reference.jl")` として読み込みます。既存の `ratings.json` をJSON3で読み、上記の明示的な事前、`categories=9`、二基準名で `PairedRatingReference.Target` を作ります。`fit_julia` は `ndraws`、`warmup`、`chains`、`seed` の明示を必須とし、既存のAdvancedHMC実行・診断基盤を使います。

以下は今回と同じ短い工学的制御です。十分な推定を意図した設定ではありません。

```julia
using JSON3
include("scripts/paired_rating_reference.jl")
A = PairedRatingReference
ratings = JSON3.read(read(
    "results/workflows/20260921-synthetic-application-01/example/ratings.json", String))
prior = (word_sd=1.0, rater_sd=(0.5,0.6), step_sd=(0.7,0.8),
    recording_log_sd_mean=(log(0.5),log(0.6)), recording_log_sd_sd=(0.5,0.6),
    person_lkj_eta=2, recording_lkj_eta=5)
target = A.Target(ratings; categories=9,
    criteria=["ease_of_understanding", "weak_accent"], prior)
result = A.fit_julia(target; ndraws=8, warmup=8, chains=2,
    seed=92161, step_size=0.01, max_depth=4, init_jitter=0.01)
folder = mktempdir(mkpath("results/paired_rating_reference"); cleanup=false)
A.save_result(joinpath(folder,"samples.jls"), result)
reopened = A.load_result(joinpath(folder,"samples.jls"))
summary = A.report(reopened)
```

Stanは `compile_stan(new_directory)` で新しい作業先にコンパイルし、その記録を `fit_cmdstan(target, compiled; ...)` に渡します。事前コンパイル済みヘッダーの作成を無効にし、共有CmdStanディレクトリへのコンパイラ固有の書込みを避けます。ソースと実行ファイルのハッシュを照合し、各保存drawの正規化されたlog posteriorと評定別log likelihoodをJuliaで検算します。永続的な自動コンパイルキャッシュは追加していません。

`save_result(path, record)`／`load_result(path)` は新しい参照用記録を使い、既存の通常fitの保存形式とは別です。入力・事前・標本を保存し、チェックサム、ターゲット、チェーン配置、保存log posteriorを再検証します。Serializationを用いるため、信頼できるファイルを対応するJulia環境で読む用途です。`report(record)` はモデル座標の区間・MCSE、サンプラー座標とモデル座標それぞれの診断、サンプラー警告・warmup記録を再生成します。rhoの区間やMCSEは、zの値を要約してから変換するのではなく、各drawのrhoから計算します。

実際にJulia 1.12の記録を1.10で読む試験では、Serializationの版30を版24の読取器で読めず拒否されました。版をまたぐJLS互換性は主張せず、各版で生成・保存した記録の再読込みを確認しています。JSONレポートには通常のJSONとして要約・診断が保存されますが、完全なfitの移植形式にはしていません。

## 事前予測と既知／未知録音の予測

[予測実装](../../scripts/paired_rating_predictive.jl)は同じ参照モジュールに含めます。新たな推定や外部パッケージは必要ありません。`prior_draws` は白色化変数、語難易度、評価者、ステップ、録音log-SD、二つの相関を**共同事前分布から**生成します。評価者とステップは独立な全要素を生成してゼロ和に射影し、その最初のn−1要素を保存します。白色化された話者変数へ相関を二重に適用しません。相関には `(rho+1)/2 ~ Beta(eta,eta)` を使います。

```julia
check = A.prior_predictive_check(target;
    ndraws=256, parameter_seed=92172, prediction_seed=92173)
# 各列は category_columns が示す基準・カテゴリーに対応する。
check.category_expected_by_draw
check.category_replicated
check.observed_category_frequencies
```

この確認は、入力に出現する水準と評定行の配置に条件付けます。観測スコアは比較用の頻度にだけ使い、パラメータ生成には使いません。割当や欠測過程を新たに生成する検証ではなく、実際の欠測が無視可能だという根拠にもなりません。数値表現の限界に達したdrawや好ましくない評定分布を、引き直して隠しません。二つのseed、事前、自由座標のdraw、出力列のラベルを返します。

推定後の予測には、スコアを含まない `person, word, rater, recording, criterion` の5フィールドだけを渡します。`prediction_rows(target)` は学習時の観測行からこの設計を取り出します。予測の出力行は入力順を保ち、録音・評価者・基準による内部の乱数割当順は固定します。

```julia
design = A.prediction_rows(target)
existing = A.posterior_predict(reopened, design;
    recording_effect=:existing, seed=92174, integrations=1)

# future_rows は学習に含まれない話者×語の組の設計行。
# 話者・語・評価者・基準はすべて学習データの既知水準でなければならない。
future = A.posterior_predict(reopened, future_rows;
    recording_effect=:new, seed=92175, integrations=256)
```

| 予測対象 | 録音効果と入力の条件 | この結果だけでは示せないこと |
| --- | --- | --- |
| 既知録音 `:existing` | 保存された各共同drawの `u` を使う。録音IDと話者×語の組は学習時と一致する。学習で欠けた評価者・基準の行も、他の水準が既知なら指定できる | 同じデータへの適合から未知録音への性能を結論できない |
| 未知録音 `:new` | 各パラメータdrawのSD・相関から新しい二次元 `u` を生成し、数値積分する。録音IDと話者×語の組の両方が学習に不在である | 新話者・新語・新評価者への一般化、同じ話者×語の再録音、欠測の無視可能性 |

現在のモデルは1話者×語に1録音です。観測済みの組を別IDへ改名して未知録音と称する入力は拒否します。録音を保留して予測性能を調べる場合は、同じ録音の**二基準・全評価者の全行**を学習から除き、そこで推定した結果を使います。一部だけ除いて推定済みの `u` を使う方法は未知録音予測にはなりません。唯一の産出が除かれて語水準自体が学習から消える場合も拒否します。今回の保存標本による応用例は未観測の組への仮想的な予測であり、保留データの性能評価ではありません。

新しい `u` は、各反復の各録音に一つだけ生成し、その二次元値を全評価者・二基準に共有します。その条件下で個々のスコアを生成します。したがって、録音効果を0に置くだけの予測や、行ごとに独立な録音効果を生成する予測とは異なります。`simulate_prediction` の録音効果・確率・スコアを使うと一反復の対応を調べられます。`probabilities` は行別の**周辺**カテゴリー確率であり、その積は共同予測確率ではありません。相関を変えても一基準の録音効果の周辺分布は変わりませんが、二基準を一緒に生成したときの依存は変わります。

`prediction_summary` は全てのパラメータdrawを使い、未知録音では各drawあたり `L=integrations` 回生成します。行別確率の平均、全カテゴリーの累積確率、draw別の期待頻度と反復データの頻度を返します。基準ごとに録音へ等しい重みを置き、同じ録音内では指定された評価者へ等しい重みを置きます。片方の基準が全欠測の録音はその基準の分母には入りません。基準別の録音数・行重みも保存し、異なる基準が同一録音集合とは限らないことを明らかにします。二基準の指標を一つにまとめる場合の等基準重みや、等話者重みの別の対象量は、この出力へ自動的に混ぜません。

`integration_mcse` は、与えられたS個のパラメータdrawに条件付けた録音効果の数値積分誤差だけです。各drawのL個の確率の標本分散を `v_s` とすると、平均のMCSEは `sqrt(sum(v_s/L))/S` です。集計頻度のMCSEも、共有録音が生む行間依存を保った反復ごとの集計から計算します。既知録音ではこの追加積分がないため0です。**これは予測の不確実性が0、事後MCMC誤差が0、あるいは収束したという意味ではありません。** `category_replicated` のS×L行は独立した事後drawではなく、同じパラメータdrawをL回共有しています。

`posterior_predict` は保存記録を再検証し、出典ハッシュ、全drawのチェーン・反復番号、raw／モデル座標の診断、サンプラー警告、warmup記録を予測へ引き継ぎます。予測確率が滑らかであっても、元の推定の問題は解消されません。現在の短い標本はこの制約を持つため、応用上の話者順位や二尺度の必要性を解釈しません。

## 事前の機構を分けた後続確認

[尺度・ステップ形状の検討](paired-rating-prior-review.md)では、同じ256個の事前drawを使って7条件を比較しました。語・評価者・録音のSDを半分にした場合、端点確率は約8ポイント低下しました。同じステップ値を昇順にすると約21–22ポイント低下し、幅のある一意の最頻領域を持つカテゴリー数は平均3.6–3.8個から9個になりました。

並び替えによる端点確率の非増加は反応式からも導出し、独立した小条件検査で確認しています。これは昇順事前を選定したという結論ではありません。同じ値の並び替えでも事前の支持領域・各位置の分布が変わるため、現在のfitへそのまま適用できません。後続文書には、この科学的判断と、保存標本からの焦点対比・確率のMCSE、費用・停止条件の提案を分けて記録しました。

## 次の判断と完了条件

1. **事前の応用上の妥当性を判断する。** 後続確認で明らかになった中間カテゴリーの役割を、評定尺度の意味に照らして検討する。単に観測頻度へ近づける調整はしない。位置・尺度の識別と二つの相関の役割を科学的レビューで確認し、感度検討する事前を目的とともに固定する。
2. **検証済みの焦点精度処理と資源監視を、目的を固定した試行へ接続する。** [保存標本による精度評価と限定監視テスト](paired-rating-precision.md)は完了した。十分な推定の確認は未実施であり、目的・明示候補・共有予算・コンパイルと出力先・監視環境を固定してから別に扱う。予測再生の計算量を長いチェーンの費用見積りに転用せず、失敗・打切りを全試行分母に残す。主MGMFRMの受入準備を、この応用試行の完了まで止めない。

4. **受入後に利用範囲を広げる。** 受け入れられたモデルと主張に対して通常API、初見利用者の再現、全体CIとリリースの条件を満たす。応用例の完成と、パッケージ全体の科学的受入を同一視しない。
