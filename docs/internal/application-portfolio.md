**現在の状態（2026-10-09）：ショパンは第1段階の氏名付き分析入力と既存一次元モデルへの接続まで、Uchiharaは実データの構造点検と合成A0の推定・予測接続まで。両者の実データ分析は未完成。** 第6節に現在の基盤との対応を、[ショパン分析仕様](chopin-stage1-analysis.md)に入力の受入と推定前の事前分布の検討事項を記録する。

## 2. EVA：大規模な多属性評定として有望

出典は[著者の公開リポジトリ](https://github.com/kang-gnak/eva-dataset)、コミット `fb40a9f1abe4be96b69229aaac3d0838a2e1d31c` の [`data/votes_filtered.csv`](https://github.com/kang-gnak/eva-dataset/blob/fb40a9f1abe4be96b69229aaac3d0838a2e1d31c/data/votes_filtered.csv)。原著は Kang, Valenzise, Dufaux (2020), [EVA: An Explainable Visual Aesthetics Dataset](https://doi.org/10.1145/3423268.3423590)。今回はREADME、出版社の抄録、CSVを確認した。原著全文とフィルタリング手順の再現は未確認であり、フィルタ済み標本を無選抜標本とは扱わない。

固定したCSVの全行を検査した結果：

| 検査項目 | 結果 |
| --- | ---: |
| 画像×評価者の評価機会 | 136,943 |
| 画像数／評価者数 | 4,070／1,094 |
| 同じ画像×評価者IDの重複 | 0 |
| 画像当たり評価機会（最小／中央値／最大） | 30／33／46 |
| 評価者当たり評価機会（最小／中央値／最大） | 1／27／4,066 |
| １件のみ／５件未満の評価者 | 8／125 |
| 画像と評価者の二部グラフ | １連結成分、5,164頂点 |
| ４属性を縦持ちにした評定行数 | 547,772 |

属性は `visual`, `composition`, `quality`, `semantic` で、各1–4。総合得点 `score` は0–10である。CSVは区切り文字 `=`、評定値は `3.0` のように保存されている。今回の５列は全行で整数値かつ定義内であり、各定義カテゴリーの観測があった。画像ファイル・評価者の個人属性・未フィルタの評定は取得していない。連結性は尺度を結び付ける設計上の確認であり、多次元モデルの識別や推定精度の証明ではない。

評価者一貫性を主対象にする場合、フィルタが不一致な評定・評価者を除いていれば、推定対象の分布も変わる。今回その除外機序は確認できていないため、実データ分析では原著の処理規則、原評定との対応、除外前後の標本を確認する。フィルタ済みデータでの良好な適合を、処理前の評価者集団全体への性能と読み替えない。

考えられるモデル上の対応は、画像を測定対象（APIの `person`）、人間の評価者を `rater`、属性への質問を `item` とするもの。ただし、これは応用設計の候補である。画像IDを項目にして対象者を捏造したり、属性名だけからQを確定したりしない。

４属性にQの単位行列を割り当てると、各次元は１種類の属性質問だけを持つ。多くの評価者がいるため反復情報は増えるが、異なる内容の指標が増えるわけではない。固定された潜在分散、負荷量、評価者効果、閾値の制約に依存する推定と、構成概念としての次元の支持を分ける必要がある。**単一指標なので無条件に推定不能と断定することも、Q検証を通るので構成概念が妥当と判断することも避ける。** まず一因子の多属性基準モデルや属性ごとのモデルが何を仮定するかを明示し、多次元化がどの問いに答えるかを決める。

総合得点と４属性は尺度が違う。現行の共通 `category_levels` に0–10を指定して属性の5–10を可能な反応として扱うと、質問の構造を変えてしまう。先に属性評定と総合評定を別の分析対象として保ち、同時モデルが必要なら項目別のカテゴリー集合と異尺度の尤度を基盤側で検証する。総合得点を説明・予測対象にする場合、同じ評価機会の属性を説明変数として使う予測と、未知の評価者・画像への予測を分ける。

４属性は同じ画像×評価者の評価機会から得られるため、ハローや残差依存があり得る。１属性だけを除外するCVと、画像×評価者の４属性をまとめて除外するCVは問いが違う。分割用の評価機会IDを `occasion` などのメタデータとして保ち、既存対象・既存評価者への新しい評価機会、新しい画像、新しい評価者を区別する。メタデータ列を加えただけでは依存効果は推定されない。

## 3. Chopin：採点過程と欠測を検討する応用

出典は[公式公開ページ](https://www.chopincompetition.pl/en/newsroom/19th-chopin-competition-judges-scores?id=144&type=news)、そこから取得した[審査員別得点表（７ページ）](https://storage.nifc.pl/web_files/_plik/file_manager_pmp/files/475810_Chopin_Competition_2025_scores.pdf)と[審査規則（６ページ）](https://storage.nifc.pl/web_files/_plik/file_manager/files/813353_Rules_Jury_last_02.10.ENG.pdf)。得点表の第１・最終ページを画像でも確認した。全表のテキスト抽出では補正前の行 `punktacja` と補正後の行 `p. kor.` を区別した。

| 段階 | 演奏者数 | 数値の補正前評定数 | `s` のセル数 |
| --- | ---: | ---: | ---: |
| 第１段階 | 84 | 1,395 | 33 |
| 第２段階 | 40 | 667 | 13 |
| 第３段階 | 20 | 331 | 9 |
| 最終段階 | 11 | 182 | 5 |

各演奏には17審査員の欄がある。全155演奏×17欄＝2,635セルを抽出し、2,575個の数値評定と60個の `s` を区別した。規則の「原則10名以内」という記載と実際の最終段階11名は区別する。後段階の演奏者IDが前段階の部分集合であることも検査した。

規則上、全段階で補正前得点は1–25の整数である。今回の実際の最小値は段階順に8、12、14、15で、最大値はいずれも25だった。下端が観測されないからといって尺度を8–25へ自動変更しない。25カテゴリーに対して得点が上側に集中するため、閾値の情報量と事前への依存を確認する必要がある。

`s` は規則が定義する学生・関係者への審査辞退を表す。対応する補正後の `0,00` は数値の最低評定ではない。さらに、補正得点は他の審査員の得点から求める平均に依存する。第１段階では平均±3、以降は平均±2の範囲へ切り詰める規則を全2,635セルへ再適用し、表示丸めの範囲内（最大0.005）で一致した。平均欄も表示丸めを含めて照合した。これは抽出の構造検査であり、名前・ID対応を含む正式な分析入力の受入ではない。

モデルへの入力候補は補正前の整数得点であり、補正後得点は制度上の比較対象として保つ。両方を独立した２評定として積み上げたり、補正後の小数を丸めて生得点扱いしたりしない。

公開表には各段階の総合得点があり、技術・表現等の基準別得点はない。したがって最初の応用は、一段階内の演奏×審査員を用いたMFRM/GMFRM相当の測定や、明示した仮定下での段階別の記述が自然な候補である。MGMFRMの応用体系には、単純なモデルで十分なデータを適切に扱う例も含められる。多次元モデルを必ず適用する必要はない。

段階を項目・機会として結ぶ場合、演奏内容と能力の発現が変わること、前段階の評価等に基づく選抜、共通参加者の減少を扱う。段階の違いを潜在次元の違いと自動的に同一視せず、段階間で尺度を結ぶ根拠を示す。辞退と未進出は異なる欠測理由であり、どちらも最低点ではない。観測された採点差から審査員の動機や不公正を識別することはできず、モデル上の調整順位を公式審査の置き換えとも扱わない。

## 4. 基盤の優先順位

1. **まず宣言したMGMFRMの基礎を確かめる。** 現在の独立２次元・固定Qモデルについて、数値計算の確認に続き、既知真値からの回復、共同事前からのSBC、独立データ反復での予測、事前感度を進める。現在完了したR0の５分割CVは１データセットであり、５反復ではない。相関次元、mixed-Q、疎デザインへの主張は別に検証する。
2. **観測と予測の単位を保つ。** 対象者・項目・評価者の係数用IDと、録音・画像評価機会・演奏等のグループ用IDを区別する。どの単位を除外し、何を既知条件とする予測かを明記する。実装が得点を返すことだけで、その予測課題を正しく設定できたとは判断しない。
3. **応用に共通する不足を小さく検証する。** 疎な割当、少数評定者、未使用カテゴリー、異尺度、局所依存、未知水準の予測、選抜を同時に新規実装しない。既存の設計監査・依存構造・固定Qの検査を再利用し、支持する機能・現在の制限・別の研究課題を区別する。
4. **応用は基盤の検証済み範囲に合わせて段階的に扱う。** Uchiharaだけで到達基準を決めない。EVAの大きさだけで性能最適化を最優先にせず、Chopinに合わせて根拠のない次元を追加しない。実データ用の取り込み処理や図表は、具体的な問いとモデル対応が決まった段階で作る。

## 5. 今回の共通実装と確認範囲

`kfold_plan` は既に任意の登録済みメタデータ役割でまとめて分割できる。一方、自動 `kfold_refit` / `loo_refit` は全メタデータ水準の訓練内存在を要求し、同一機会を丸ごと除外すると係数を持たないIDまで拒否していた。さらに得点計算用のデータ再構成も、そのIDを訓練の水準表へ厳密に照合して失敗していた。

現行の対応尤度では任意列はメタデータなので、実行時の訓練支持の検査を person/rater/item/category に限定し、得点計算用のメタデータ水準表には未知ラベルを追加するよう修正した。訓練データや係数は追加せず、元のラベルと既知水準の対応を保つ。一般的な `kfold_plan_diagnostics` は従来どおり全役割を監査する。依存効果や新しい対象者・項目・評価者への予測を実装した変更ではない。

また、グループで分割しても、現行の得点は観測ごとの周辺予測log scoreである。その和はグループ全体の同時予測log scoreではない。返される標準誤差も観測行の変動に基づく計算であり、グループ内依存を調整したものではない。応用での比較には、予測対象に即した集約と不確実性の評価が別に必要である。この区別を利用説明にも明記した。現行のカテゴリー支持の保守的な制限は残り、未使用カテゴリーの扱いを今回一括変更していない。

新しい回帰テストは、修正前に拒否を再現し、修正後は３モデル系統の実際の小さいrefit、メタデータの有無によるdraw・得点の一致、ラベルの復元、未知係数水準の拒否を確認する。これはソフトウェア検証であり、短いテストfitから推定の収束や科学的な性能を主張しない。

追加44件はJulia 1.12.5・1.10.8の両方で通過した。Julia 1.12.5では、追加44件を含む `fitting_core` の25 testset、計5,638件が標準 `Pkg.test` 環境で通過した。最初の直接起動ではテスト専用依存のReverseDiffが見つからず、offlineの標準テスト環境へ切り替えた。全CIを実行した記録ではない。取得した入力のハッシュと検証中のソース一致も確認し、既存の科学的評価結果は変更していない。

[`20260923-application-scope-01`](../../results/workflows/20260923-application-scope-01/) に保存した。
EVAの未フィルタデータと原著全文、Chopinの氏名対応を含む完全な取り込み、実データの推定、EVA全量での速度・メモリ検証は未実施である。

### 既存A0と新しい共有課題モデルの関係

[A0参照](paired-rating-reference.md)と[新しい4ファセット試作](shared-effects-hierarchy-prediction.md)は、共有効果を持つという共通点があっても、現在は別のモデルである。

| 項目 | 合成UchiharaのA0 | 新しい共有課題試作 |
| --- | --- | --- |
| 能力の相関 | 2基準間の相関を推定 | 2次元の相関はidentityに固定 |
| 録音／共有効果 | 二次元の録音効果、基準別SDと録音相関を推定 | 一つのperson×task効果を全観点へ+1で共有、単一SDを推定 |
| 課題・評定者 | 語×基準の難易度、評定者×基準の厳しさ | 共通課題難易度＋観点効果、共通評定者厳しさ |
| 支持する配置 | 2基準、疎な話者×語、片方の基準欠測を許す | 完全交差、各次元2観点以上。現在の2次元版は最低4観点 |
| 予測 | 既知録音と限定した未知録音の積分を実装 | 元学習行の既存効果に条件付けた予測 |

したがって、新試作の144行・35パラメータのfit成功を、A0の736パラメータやUchihara実データの受入へ移さない。2基準の元データを新試作へ合わせるため観点を複製したり、137不在産出を補完して完全交差にしたりしない。A0で既に実装した相関・疎配置・未知録音の処理を作り直すことも次の目標ではない。共通化する場合は、観測／予測の契約や診断・保存処理から始め、式・制約・事前が同じかを別に照合する。

### 基盤の次の成果物と、API確定後に再開する応用

| 順序・対象 | 次に完了させる成果物 | その段階の終了条件 |
| --- | --- | --- |
| 主経路：現行基盤 | pilot確定→同一ターゲットの効率比較→採用実装の固定→fresh main | 既定の分母、失敗、精度条件を保った評価。応用の完成や追加のモデル拡張を前提に増やさない |
| 共通API確定 | 選択したモデル範囲の仕様と、推定→診断→予測→保存／復元の一貫した利用経路 | 合成例で契約と対応する検証を確認し、版・互換性・支持範囲・制限を記録する。実データ用の個別スクリプトを増やすことはこの終了条件の代わりにならない |
| API確定後：ショパンの分析設計 | 受入済みの第1段階入力を使った事前予測と分析仕様の確定 | [既存一次元モデルの事前](chopin-stage1-analysis.md)を、審査員の基準依存・ステップ分散・得点分布から点検。採用事前、感度候補、焦点量、診断・MCSE条件を推定前に固定する。氏名／ID／出典対応、1,395生得点＋33辞退、宣言尺度1〜25の入力受入は保存済み |
| API確定後：ショパンの最初の分析例 | 演奏・審査員の差と不確実性を説明する再現可能なレポート | 確定したAPIの支持範囲内で推定・診断・事前感度・カテゴリ支持を報告。データと条件をそろえた生得点／公式補正との比較を示す。技術・表現等の未観測次元や不公正の判定は付け足さない |
| 必要な基盤課題に限る：合成A0の再利用 | 相関・録音内依存・疎配置など、選択したモデル/APIの問いに対応する検証 | 既存実装と保存結果を再利用し、追加推定は基盤の明示した課題と精度条件に結び付ける。合成応用レポートの完成を主経路やAPI確定の条件にしない |
| API確定後：Uchihara実データ | 原資料との対応を確定した分析入力と、観測産出に条件付けた分析の問い | 公開配布・論文の分析集団・カテゴリ方向・欠測の扱いを照合。12話者からの母相関と少数話者しか持たない語の情報不足を報告。必要な相関・依存構造が確定APIの支持範囲に入ることを確認し、合成例の実装完了と実研究の結論を区別 |

ショパンの一次元例に、相関MGMFRMや4ファセットの全機能は必要ない。一方、Uchiharaの二基準の関連という問いには相関と録音内依存の扱いが必要で、現在の独立2次元pilotの合格だけでは足りない。それぞれに必要な最小の経路を使う。

運用上は、pilot実行中の独立作業を共通APIの仕様整理と基盤課題に必要な検証へ向け、固定ソースを維持する。応用入力の追加整備・応用固有の事前選択・実データ推定は、対応するAPI確定後へ移す。審査員基準やステップの事前の非対称性は、実データへの当てはまりで選ぶ前に制御された合成例で扱える。新しい反復数・計算条件は対象ごとに事前宣言し、経過時間の上限は設けず、ローカル資源の実測とメモリ／保存量の監視を維持する。9月文書中の時間上限案は現在のユーザー方針を上書きしない。EVAも同じ順序の待機候補とする。
